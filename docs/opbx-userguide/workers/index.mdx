# Worker Services

OPBX uses standalone worker services for specialized runtime tasks:

| Worker | Technology | Purpose |
|--------|------------|---------|
| [Dialer Worker](/workers/dialer-worker) | Go | Executes outbound auto-dialer campaigns |
| [AMD Worker](/workers/amd-worker) | Java/Vert.x 5 | Detects voicemail beeps in live audio streams |
| [ACD Worker](/workers/acd-worker) | Java/Vert.x 5 | Runs call queue state (FIFO, agent states, selection strategies) |

All workers run as Docker services in the standard Docker Compose stack. They communicate with the Laravel backend through REST APIs and Redis.

## When to Read These Guides

Read the worker guides when you need to:

- Understand how outbound campaigns are executed
- Build or run a worker locally
- Configure worker environment variables
- Troubleshoot campaign or AMD issues
- Scale the dialer worker horizontally

## Common Commands

### View Worker Logs

```bash
docker compose logs -f dialer-worker
docker compose logs -f amd-worker
docker compose logs -f acd-worker
```

Or enable the [centralized logging stack](/administration/centralized-logs) to search all worker logs (and Laravel's) in one place, including per-call audit trails by Cloudonix session token.

### Scale the Dialer Worker

```bash
docker compose up -d --scale dialer-worker=3
```

### Restart a Worker

```bash
docker compose restart dialer-worker
docker compose restart amd-worker
docker compose restart acd-worker
```

:::tip
Wait 120 seconds after restarting the full stack before testing worker functionality.
:::
