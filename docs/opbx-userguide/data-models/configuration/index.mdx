# Configuration Reference

This page documents the environment variables and configuration values used by OPBX.

## Environment Variables

### Core Application

| Variable | Default | Description |
|----------|---------|-------------|
| `APP_NAME` | `OPBX - Open Source Business PBX` | Application name |
| `APP_ENV` | `production` | Environment mode |

### S3 Storage (SeaweedFS)

The `MINIO_*` variable names are kept for the S3 client. The S3 store is SeaweedFS; on AWS, point the endpoint and keys at real S3.

| Variable | Default | Description |
|----------|---------|-------------|
| `MINIO_ACCESS_KEY` | `minioadmin` | S3 access key (SeaweedFS identity). Must not be a weak value; the container entrypoint rejects them. |
| `MINIO_SECRET_KEY` | `minioadmin` | S3 secret key. Same rule as the access key. |
| `MINIO_REGION` | `us-east-1` | |
| `MINIO_BUCKET` | `recordings` | Default bucket |
| `MINIO_ENDPOINT` | `http://seaweedfs:8333` | S3 API endpoint |
| `MINIO_USE_PATH_STYLE` | `true` | |
| `MINIO_EXPOSE_PORT` | — | Expose the S3 API on loopback port 8333 (dev only, needs `docker-compose.ports.yml`) |
| `MINIO_CONSOLE_EXPOSE_PORT` | — | Expose the SeaweedFS master UI on loopback port 9333 (dev only, needs `docker-compose.ports.yml`) |
| `CDR_ARCHIVE_BUCKET` | `cdr-archive` | Private bucket for the cold call-record archive. Same credentials as above |

The `MINIO_*` names are kept for compatibility. Existing installations that used MinIO move their objects with `scripts/migrate-minio-to-seaweedfs.sh`. The upgrade steps are in `docs/DATABASE-PERSISTENCE.md` in the repository.

## Data Retention

Retention periods are set in days (or hours where noted) and enforced by the scheduler. Set a variable to an empty value to turn pruning off for that data. The pruning runs daily at 03:00 (`model:prune`); the CDR tiers and recording expiry run at 04:00 and 04:30 UTC.

| Variable | Default | Data |
|----------|---------|------|
| `RETENTION_SESSION_UPDATES_DAYS` | `30` | Live call-state updates |
| `RETENTION_CALL_NOTIFICATION_LOGS_DAYS` | `90` | Call notification delivery logs |
| `RETENTION_EMAIL_LOGS_DAYS` | `90` | Email logs |
| `RETENTION_BLOCKED_CALL_LOGS_DAYS` | `90` | Blocked-call logs |
| `RETENTION_QUEUE_CALLS_DAYS` | `183` | Call-queue call records (deleted, not archived) |
| `RETENTION_CALL_TRACKING_SESSIONS_DAYS` | `183` | Call-tracking sessions (deleted) |
| `RETENTION_AUTO_DIALER_CALL_SESSIONS_DAYS` | `183` | Auto-dialer call sessions (deleted) |
| `RETENTION_PLATFORM_AUDIT_LOGS_DAYS` | `365` | Platform audit log |
| `PLATFORM_HEALTH_RETENTION_HOURS` | `24` | Platform Status history, in **hours** |

### Call detail records (tiered)

Call records are not pruned. They move through three tiers, by session time in UTC:

| Variable | Default | Meaning |
|----------|---------|---------|
| `CDR_HOT_MONTHS` | `6` | Months kept in the main database |
| `CDR_WARM_MONTHS` | `12` | Age at which a record leaves the warm archive table and is written to a cold archive file |
| `CDR_COLD_RETENTION_YEARS` | `7` | Years a cold (compressed CSV) archive file is kept |
| `RECORDING_RETENTION_MONTHS` | empty | Months a call recording is kept. Empty means the cold retention period. A larger value is reduced to the cold retention period |

The warm tier is the `archived_call_detail_records` table on the `cdr_archive` connection. Without `DB_CDR_ARCHIVE_DATABASE` it lives in the main schema. To use a separate schema, create it, grant the app user, and set `DB_CDR_ARCHIVE_DATABASE` (and optionally `DB_CDR_ARCHIVE_HOST`, `_PORT`, `_USERNAME`, `_PASSWORD`; each falls back to the main database setting). The cold tier is written to the bucket named by `CDR_ARCHIVE_BUCKET` (default `cdr-archive`). See [Call Logs](/modules/call-logs#retention-and-archive).

## Platform Status

| Variable | Default | Meaning |
|----------|---------|---------|
| `PLATFORM_STATUS_TIMEOUT` | `2.5` | Seconds before a component probe fails |
| `PLATFORM_STATUS_SLOW_MS` | `1500` | Responses slower than this are degraded |
| `PLATFORM_STATUS_QUEUE_PENDING` | `500` | Pending jobs above this are degraded |
| `PLATFORM_STATUS_QUEUE_FAILED` | `50` | Failed jobs at or above this are degraded |
| `PLATFORM_STATUS_CLOUDONIX_SLOW_MS` | `3000` | Cloudonix answers slower than this count as slow |
| `PLATFORM_STATUS_CLOUDONIX_TIMEOUT` | `5` | Seconds before a Cloudonix check counts as no answer |
| `PLATFORM_STATUS_CLOUDONIX_CONSECUTIVE` | `3` | Consecutive bad checks before the status changes |

Each probe URL can be overridden with `PLATFORM_STATUS_*_URL`. See [Platform Management](/administration/platform-management#platform-status).

## Health Check Endpoints

| Endpoint | Auth | Purpose |
|----------|------|---------|
| `GET /api/health` | None | API liveness: `{"status":"ok","timestamp":...}` |
| `GET /api/v1/public/status` | None (cached 30 s, 60/min) | Public platform status, grouped by service |
| `GET /api/voice/health` | None | Voice routing health |
| `GET /api/storage/health` | Sanctum | Writes, reads and deletes a test object in the recordings bucket |
| `GET /api/websocket/health` | Sanctum | Sends a test event through Soketi |
| `GET /api/v1/dialer/worker/health` | Dialer worker token | Laravel side of the dialer worker API |
| `GET dialer-worker:8081/webhooks/health` | None (internal) | Dialer worker health |
| `GET amd-worker:8083/health` | None (internal) | AMD worker health and detection counters |
| `GET acd-worker:8085/health` | None (internal) | ACD worker health; 503 when Redis does not answer |
| `GET mcp-server:8080/health` | None (internal) | MCP server health |
| `GET soketi:9601/ready` | None | Soketi readiness |

The internal endpoints are what the Docker healthchecks call. Platform Status (`platform:health-check`, every minute) probes all components and stores the results in `platform_health_checks`.

| `mcp-server` | `opbx_mcp` | MCP server for AI assistants |
| `ngrok` | `opbx_ngrok` | Webhook tunnel. Profile `dev` only |

Services are started with `docker compose up -d`. Optional services need a profile:

| Profile | Starts |
|---------|--------|
| `dev` | ngrok tunnel for local webhook testing |

Host ports for the database, Redis and SeaweedFS are not published by default. `docker-compose.ports.yml` adds loopback ports for development.
