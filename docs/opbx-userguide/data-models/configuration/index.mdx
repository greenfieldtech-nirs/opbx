# Configuration Reference

This page documents the environment variables and configuration values used by OPBX. The **Default** column shows the value in `.env.example` (or in `docker-compose.yml` for variables that only the compose file reads). Where the code falls back to a different value when the variable is unset, the description says so.

### Webhooks / Rate Limiting

| Variable | Default | Description |
|----------|---------|-------------|
| `RATE_LIMIT_API` | `60` | API requests per organization per window (`rate_limit_org:api` on the `/api/v1` resource routes). Also the `api` named limiter, which no route applies |
| `RATE_LIMIT_API_MINUTES` | `1` | Window, in minutes, for `RATE_LIMIT_API` |
| `RATE_LIMIT_DEFAULT` / `RATE_LIMIT_DEFAULT_MINUTES` | `60` / `1` | Fallback per-organization limit for any other `rate_limit_org:<type>` (none is applied today) |
| `RATE_LIMIT_SENSITIVE` | `10` | Sensitive operations per minute (`throttle:sensitive`, and the `sensitive-operations` middleware for users who are not Owner or PBX Admin) |
| `RATE_LIMIT_SENSITIVE_ADMIN` | `60` | `sensitive-operations` limit for Owners and PBX Admins |
| `RATE_LIMIT_SENSITIVE_DECAY` | `60` | Seconds a `sensitive-operations` hit counts |
| `RATE_LIMIT_AUTH` | `5` | Auth attempts per minute per IP (`throttle:auth`) |
| `WEBHOOK_IDEMPOTENCY_TTL` | `86400` | Seconds a webhook idempotency key (`idem:webhook:{key}`) is kept |
| `WEBHOOK_MAX_CACHE_SIZE` | `102400` | Largest response (bytes) cached for a duplicate webhook |
| `WEBHOOK_REPLAY_MAX_AGE` | `300` | Webhooks with an older `timestamp` are rejected (CDRs are accepted with a log line) |

Cloudonix webhook and voice routing routes are intentionally **not rate-limited**: with many organisations Cloudonix sends hundreds of events per second, and throttling them would drop calls and CDRs. They are protected by authentication and idempotency instead.

The values above are in `config/rate_limiting.php`. Other limits are fixed in code: `registration` (10 per hour per IP; `config('rate_limiting.registration')` has no key, so the fallback applies), `call-tracking-dni` (60 per minute per organization and IP), `embed` (60 per minute per token and IP), `dialer-worker` (`DIALER_WORKER_RATE_LIMIT`, default 1000 per minute per IP), the public status page (`throttle:60,1`), and a few routes with inline `throttle:<n>,1` values.

See [Webhooks](/opbx/architecture/webhooks) for the authentication flow.

## Data Retention

Retention periods are set in days (or hours where noted) and enforced by the scheduler. Set a variable to an empty value to turn pruning off for that data. The pruning runs daily at 03:00 (`model:prune`); the CDR tiers and recording expiry run at 04:00 and 04:30 UTC.

| Variable | Default | Data |
|----------|---------|------|
| `RETENTION_SESSION_UPDATES_DAYS` | `30` | Live call-state updates |
| `RETENTION_CALL_NOTIFICATION_LOGS_DAYS` | `90` | Call notification delivery logs |
| `RETENTION_EMAIL_LOGS_DAYS` | `90` | Email logs |
| `RETENTION_BLOCKED_CALL_LOGS_DAYS` | `90` | Blocked-call logs |
| `RETENTION_QUEUE_CALLS_DAYS` | `183` | Call-queue call records (deleted, not archived) |
| `RETENTION_CALL_TRACKING_SESSIONS_DAYS` | `183` | Call-tracking sessions (deleted) |
| `RETENTION_AUTO_DIALER_CALL_SESSIONS_DAYS` | `183` | Auto-dialer call sessions (deleted) |
| `RETENTION_PLATFORM_AUDIT_LOGS_DAYS` | `365` | Platform audit log |
| `PLATFORM_HEALTH_RETENTION_HOURS` | `24` | Platform Status history, in **hours** |

### Call detail records (tiered)

Call records are not pruned. They move through three tiers, by session time in UTC:

| Variable | Default | Meaning |
|----------|---------|---------|
| `CDR_HOT_MONTHS` | `6` | Months kept in the main database |
| `CDR_WARM_MONTHS` | `12` | Age at which a record leaves the warm archive table and is written to a cold archive file |
| `CDR_COLD_RETENTION_YEARS` | `7` | Years a cold (compressed CSV) archive file is kept |
| `RECORDING_RETENTION_MONTHS` | empty | Months a call recording is kept. Empty means the cold retention period. A larger value is reduced to the cold retention period |

The warm tier is the `archived_call_detail_records` table on the `cdr_archive` connection. Without `DB_CDR_ARCHIVE_DATABASE` it lives in the main schema. To use a separate schema, create it, grant the app user, and set `DB_CDR_ARCHIVE_DATABASE` (and optionally `DB_CDR_ARCHIVE_HOST`, `_PORT`, `_USERNAME`, `_PASSWORD`; each falls back to the main database setting). The cold tier is written to the bucket named by `CDR_ARCHIVE_BUCKET` (default `cdr-archive`). See [Call Logs](/opbx/modules/call-logs#retention-and-archive).

| `GET /api/storage/health` | Sanctum | Writes, reads and deletes a test object in the recordings bucket |
| `GET /api/websocket/health` | Sanctum | Sends a test event through Soketi |
| `GET /api/v1/dialer/worker/health` | Dialer worker token | Laravel side of the dialer worker API |
| `GET dialer-worker:8081/webhooks/health` | None (internal) | Dialer worker health |
| `GET amd-worker:8083/health` | None (internal) | AMD worker health and detection counters |
| `GET acd-worker:8085/health` | None (internal) | ACD worker health; 503 when Redis does not answer |
| `GET mcp-server:8080/health` | None (internal) | MCP server health |
| `GET soketi:9601/ready` | None | Soketi readiness |

The internal endpoints are what the Docker healthchecks call. Platform Status (`platform:health-check`, every minute) probes all components and stores the results in `platform_health_checks`.

## Docker Services

| Service | Container | Purpose |
|---------|-----------|---------|
| `app` | `opbx_app` | Laravel PHP-FPM |
| `nginx` | `opbx_nginx` | Reverse proxy |
| `frontend` | `opbx_frontend` | Vite dev server |
| `mysql` | `opbx_mysql` | MySQL 8.4 LTS (`mysql_native_password` enabled for compatibility) |
| `redis` | `opbx_redis` | Cache, sessions, queues |
| `seaweedfs` | `opbx_seaweedfs` | S3-compatible object storage (SeaweedFS 4.47) for recordings, IVR audio and the cold CDR archive |
| `soketi` | `opbx_websocket` | WebSocket server |
| `queue-worker` | `opbx_queue_worker` | Queue worker |
| `queue-worker-long` | `opbx_queue_worker_long` | Queue worker for long-running jobs |
| `scheduler` | `opbx_scheduler` | Task scheduler |
| `dialer-worker` | `opbx_dialer_worker` | Go dialer worker (single replica) |
| `amd-worker` | `opbx_amd_worker` | Java AMD worker |
| `acd-worker` | `opbx_acd_worker` | Java call-queue (ACD) worker |
| `mcp-server` | `opbx_mcp` | MCP server for AI assistants |
| `ngrok` | `opbx_ngrok` | Webhook tunnel. Profile `dev` only |
| `loki`, `alloy`, `grafana`, `docker-socket-proxy` | `opbx_loki`, `opbx_alloy`, `opbx_grafana`, `opbx_docker_socket_proxy` | Log stack. Profile `logs` only |

Services are started with `docker compose up -d`. Optional services need a profile:

| Profile | Starts |
|---------|--------|
| `dev` | ngrok tunnel for local webhook testing |
| `logs` | Loki, Alloy, Grafana and the docker-socket-proxy. See [Centralized Logs](/opbx/administration/centralized-logs) |

Host ports for the database, Redis and SeaweedFS are not published by default. `docker-compose.ports.yml` adds loopback ports for development.
