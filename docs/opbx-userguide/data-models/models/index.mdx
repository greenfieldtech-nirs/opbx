# Database Models

OPBX uses Laravel Eloquent models. Most models are scoped by `organization_id` through `OrganizationScope`. Platform admin models are not tenant-scoped.

### Framework Tables

These tables belong to Laravel and have no OPBX model: `migrations`, `sessions`, `password_reset_tokens`, `cache`, `cache_locks`, `jobs`, `job_batches` and `failed_jobs`. `locks` is used by `App\Services\Fallback\DatabaseLockService`, a database lock with an `expires_at` column.

## Tenancy Notes

- Models with `#[ScopedBy([OrganizationScope::class])]` are automatically filtered by the authenticated user's organization.
- Webhook handlers and platform admin operations must use `OrganizationScope::bypass()` when querying tenant-scoped models.
- Not tenant-scoped: `Organization`, `PlatformAuditLog`, `PlatformHealthCheck`, `EmailLog`, `ApiKey`, `ApiKeyPermission`, `PersonalAccessToken`, `UserSocialIdentity` and the child tables reached through a scoped parent (`RingGroupMember`, `IvrMenuOption`, `AiAssistantLoadBalancerMember`, the business-hours days, ranges and exceptions, `AutoDialerCampaignCallerId`, `AutoDialerCallerIdStat`).
- Rows of several tables are pruned daily by retention settings; call records are tiered instead. See [Data Retention](/opbx/data-models/configuration/index#data-retention).
