# SessionUpdate Model

The `SessionUpdate` model stores real-time session update events from Cloudonix for monitoring and debugging.

**Table:** `session_updates`  
**Model:** `App\Models\SessionUpdate`

## Database Schema

| Column | Type | Nullable | Description |
|--------|------|----------|-------------|
| `id` | bigint unsigned | No | Primary key |
| `organization_id` | bigint unsigned | No | Tenant scope. Foreign key, `ON DELETE CASCADE` |
| `session_id` | bigint | No | Cloudonix session ID |
| `session_token` | varchar(64) | Yes | Token for Cloudonix API disconnect |
| `event_id` | varchar(36) | No | Idempotency key |
| `domain_id` | int | No | Cloudonix domain ID |
| `domain` | varchar(255) | No | Domain name |
| `subscriber_id` | int | Yes | Subscriber ID |
| `outgoing_subscriber_id` | int | Yes | Outgoing subscriber ID |
| `caller_id` | varchar(50) | No | Caller number |
| `destination` | varchar(50) | No | Callee number |
| `direction` | enum | No | `incoming`, `outgoing`, `internal`, `application`. Copied to the CDR at ingest |
| `status` | varchar(50) | No | Current status |
| `session_created_at` | timestamp | No | Session creation time |
| `session_modified_at` | timestamp | No | Last modification time |

## Usage Notes

- The Live Calls module queries this table to display active sessions.
- The `profile` field is the Cloudonix session profile. For auto-dialer calls it can include the AMD result, which Laravel writes to the Cloudonix profile when the AMD worker reports.
- Session updates are processed idempotently using `event_id`; the unique index on (`organization_id`, `session_id`, `event_id`) rejects a duplicate row.
- Every 15 minutes, `session-updates:cleanup` marks sessions stuck in an active state (no CDR or delete event arrived) as deleted.
- Rows whose `updated_at` is older than `RETENTION_SESSION_UPDATES_DAYS` (default 30) are pruned daily at 03:00 UTC by `model:prune`.
