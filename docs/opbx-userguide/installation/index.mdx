# Installation

OPBX runs as a Docker Compose stack. There are two ways to install it:

- **The guided installer, `./install.sh`** (recommended). It asks a few questions, writes `.env`, starts the stack and creates your owner account. See [Install with the Installer](#install-with-the-installer).
- **Manual setup**, for people who want to write `.env` themselves. See [Manual Setup](#manual-setup).

Either way, `./opbx.sh` then starts, stops and upgrades the stack (see [Starting and Stopping](#starting-and-stopping)).

## Prerequisites

| Requirement | Minimum | Recommended |
|-------------|---------|-------------|
| RAM | 4 GB | 8 GB |
| Disk Space | 20 GB (the installer stops when less than 10 GB is free) | 50 GB |
| Docker (or Podman with its Docker-compatible CLI and socket) | 20.10+ | Latest |
| Docker Compose plugin | 2.24.4+ (the compose files use `!reset` and `!override`) | Latest |
| Git | 2.30+ | Latest |

Node.js, PHP and Composer are not needed on the host: the installer and Composer run inside containers.

For production you also need a domain name with a TLS certificate and a reverse proxy (or load balancer) that terminates TLS. OPBX itself serves plain HTTP. The Web Phone only works over HTTPS.

These host ports are published by default (each can be remapped in `.env`):

| Default Port | Service | Variable |
|--------------|---------|----------|
| 80 | Nginx reverse proxy | `APP_PORT` |
| 3000 | React frontend (Vite dev server; development only) | `FRONTEND_PORT` |
| 6001 | Soketi WebSocket server (development only) | `SOKETI_PORT` |
| 9601 | Soketi metrics (development only) | `SOKETI_METRICS_PORT` |
| 4040 | ngrok web interface (only while ngrok runs) | — |
| 9443 | SafeLine WAF console, served by Nginx (only with the WAF on) | `WAF_CONSOLE_PORT` |

The production overlay (`docker-compose.prod.yml`) removes the frontend and Soketi ports, so a production host publishes only `APP_PORT` and, with the WAF on, `WAF_CONSOLE_PORT`.

MySQL, Redis, SeaweedFS, the dialer worker and the MCP server publish **no** host ports. For local tools, `docker-compose.ports.yml` adds loopback-only ports (`127.0.0.1`). A development install made by the installer includes it automatically:

| Port | Service | Variable |
|------|---------|----------|
| 3306 | MySQL | `DB_EXPOSE_PORT` |
| 6379 | Redis | `REDIS_EXPOSE_PORT` |
| 8333 | SeaweedFS S3 API | `MINIO_EXPOSE_PORT` |
| 9333 | SeaweedFS master UI | `MINIO_CONSOLE_EXPOSE_PORT` |
| 8181 | Dialer worker health endpoint (container port 8081) | `DIALER_WEBHOOK_HOST_PORT` |
| 8080 | MCP server | `MCP_PORT` |

When one of these ports is already taken, the installer offers a free port and writes it to `.env`. Never use `docker-compose.ports.yml` in production. MCP clients reach the MCP server through Nginx at `/mcp` without it.

## Install with the Installer

Who can do this: anyone with shell access to the server who can run `docker`.

### 1. Clone the repository

```bash
git clone https://github.com/greenfieldtech-nirs/opbx.git
cd opbx
```

### 2. Start the installer

```bash
./install.sh
```

Run it in an interactive terminal. It checks that `docker`, `docker compose` and the container daemon work (it finds the Podman socket by itself), builds a small installer image (`opbx-installer:local`) and runs the installer in a container. The old `./opbx_bootstrap.sh` now just runs `./install.sh`.

If OPBX is already installed, `./install.sh` instead asks **OPBX is already installed. What would you like to do?** with **Change settings** (see [Change settings later](#change-settings-later)), **Start over** (see [Start over](#start-over)) and **Exit**. An installation that was interrupted is resumed: the installer asks the questions again with your earlier answers filled in and keeps the secrets it already generated.

### 3. Answer the questions

The questions are in plain language. Press Enter to keep the value shown.

| Question | What it sets |
|----------|--------------|
| **Is this a production server or a development machine?** | **Production**: a real server reached over HTTPS. **Development**: OPBX on this computer at `http://localhost`. Sets `APP_ENV`, `APP_DEBUG` and the compose files |
| **What is your server's public address?** (production only) | The `https://` address people type, for example `https://pbx.example.com`. It must use `https://` and a real domain name. Sets `APP_URL` and the other URL values |
| **Which port on this machine should OPBX listen on?** | `APP_PORT` (default 80). The installer checks that the port is free |
| **Other host names allowed to open OPBX** (development only, optional) | Names you use to open OPBX from another machine: a VPN name (for example a Tailscale name), the machine's IP address or your ngrok domain. A name that starts with a dot (`.ts.net`) allows every name under it. Sets `VITE_ALLOWED_HOSTS`. Live updates then connect to the same name on port 6001, so let 6001 through as well as 3000 |
| **What is the IP address or network of the proxy that forwards traffic to OPBX?** (production only, optional) | `TRUSTED_PROXY_CIDR`. With it, Nginx takes the visitor's real IP from `X-Forwarded-For`, so rate limits, logs and WAF events are accurate. Without it they all see the proxy's address |
| **What is your organization's name?**, **Your full name**, **Your email address** | The first organization and its Owner. The email is used to sign in |
| **Will this server run just your company, or many customer organizations?** | **Just my company**: each organization sets its own webhook address in Settings (`OPBX_APPLICATION_MODE=development`). **Many customer organizations**: one webhook address for the whole server, your public address (`OPBX_APPLICATION_MODE=production`, `OPBX_APPLICATION_WEBHOOK_BASEURL`). Either way the sign-up page stays open: anyone who can reach the server can create an organization |
| **What should people see when they open** your address? | **The sign-in page** (recommended; people already signed in go straight to the dashboard) or **The OPBX homepage**. Sets `OPBX_FRONT_PAGE` (see [Front page](#front-page)) |
| **Which outgoing email service would you like to use?** | Mailgun, Mailjet, MailerLite, Brevo (Sendinblue) or **None for now**, then that service's keys, the sender address and the sender name. With **None**, invitation and password-reset emails are not sent |
| **Allow sign-in with Google or GitHub through Auth0?** | The Auth0 domain, client ID, client secret and providers. Sets `OPBX_SAAS_ENABLED=true` and the `AUTH0_*` values. See [Auth0 Setup](/opbx/installation/auth0-setup) |
| **Protect sign-up with Google reCAPTCHA v3?** | Site key, secret key and minimum score (0 to 1, default 0.5) |
| **Check sign-up email addresses with UserCheck?** | The UserCheck token and which kinds of address to refuse. When you answer no, `USERCHECK_ENABLED=false` |
| **Collect logs in Grafana?** | Turns on the log stack (`logs` profile). See [Centralized Logs](/opbx/administration/centralized-logs) |
| **Put a web application firewall in front of OPBX?** | **No**, **Yes, monitor only** (recommended to start) or **Yes, blocking**, then the firewall's data folder (default `/var/lib/safeline`), the console port (default 9443) and who may open the console. See [SafeLine WAF](#safeline-waf) |
| **ngrok auth token** (development only, optional) | Lets Cloudonix reach your development machine. Sets `NGROK_AUTHTOKEN` and starts ngrok with the stack |
| **Review advanced settings?** | Optional: request limits per minute, how long old records are kept, routing cache lifetimes, Cloudonix connection protection and log detail |

### 4. Review and confirm

The installer lists your answers (secrets are hidden) and asks **Is this correct?** Choose **Yes, continue**, or **No, go back and change something** to answer again with your answers filled in. Nothing is written before you confirm.

{/* SCREENSHOT: installer-review — terminal running ./install.sh, the "Please review your choices (secrets are hidden)" box with the answers of a development install, and the "Is this correct?" choice */}

### 5. Prepare the firewall data folder (WAF only)

With the WAF on, the installer shows **Prepare the firewall data folder**: a few commands that need administrator rights (`sudo mkdir …`, a small detector configuration file, and on SELinux hosts a `chcon` command). Run them in another terminal on the same machine, then go back to the installer. It checks the folder and asks again until everything is in place. With Podman on macOS, run them inside the Podman VM (`podman machine ssh`).

### 6. Wait for the build and the first start

The installer then:

1. writes `.env` (from `.env.example`), `docker-compose.yml` (a copy of `docker-compose.yml.example`) and, with the WAF on, `docker/safeline/.env`;
2. generates every secret (database, Redis, application key, worker tokens, Soketi, S3 keys, Grafana);
3. builds the images and installs the PHP packages inside the app image;
4. starts the stack in order (SafeLine first when the WAF is on) and waits for each service;
5. creates your organization and its Owner, who is also a platform manager;
6. runs checks: services, web app, API, WebSocket, storage buckets and the WAF. A failed check offers **Check again** or **Stop here**;
7. offers to send a test email when you chose an email service.

The first build takes several minutes.

If `docker-compose.yml` already exists and differs from `docker-compose.yml.example`, the installer offers to back it up (`docker-compose.yml.bak-<timestamp>`) and replace it.

### 7. Store the owner password

As soon as the owner exists, the installer shows **Write this down now** with the owner's email and the generated password. The password is shown only here and in the final summary.

The final summary (**Installation complete**) lists the URLs, the owner login, the Grafana and WAF admin logins when those are on, the reverse proxy settings for production, and the next steps. It is also saved to `opbx-install-summary.txt` in the repository folder (mode 600, ignored by git). Store the passwords, then delete that file.

{/* SCREENSHOT: installer-summary — terminal at the end of ./install.sh showing the "Installation complete" summary: Checks all ok, URLs, Owner login (password blurred) and Next steps */}

To set a new owner password later:

```bash
docker compose exec app php artisan user:reset-password <email>
```

### 8. Point your reverse proxy at OPBX (production)

OPBX does not terminate TLS. In your reverse proxy, forward your domain to the OPBX Nginx port (`APP_PORT`) with WebSocket upgrade headers. The summary prints a ready-to-paste Nginx example:

```nginx
# Inside your existing server { } block for pbx.example.com (the one with its TLS certificate):
    client_max_body_size 50m;
    location / {
        proxy_pass http://<this-server>:80;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 3600s;
    }
```

With the WAF on, the snippet adds a second `server { }` block that forwards the console port with the same certificate. If the proxy runs on the OPBX server itself, choose a console port the proxy does not listen on. Make `APP_PORT` (and the console port) reachable only from the proxy.

Then go to [First Login](/opbx/installation/first-login). For a server that runs **just your company**, also connect Cloudonix in **Settings** (see [Cloudonix Integration](/opbx/installation/cloudonix-setup)).

### What the installer writes

| File | Contents |
|------|----------|
| `.env` | Every setting and secret. Mode 640, owned by you with group 82 (`www-data` in the app image, which reads it) |
| `docker-compose.yml` | A copy of `docker-compose.yml.example` |
| `docker/safeline/.env` | SafeLine's own settings and secrets (WAF only; mode 600) |
| `opbx-install-summary.txt` | The summary, with the passwords (mode 600) |

Besides the values from your answers, `.env` gets these installer keys:

| Variable | Purpose |
|----------|---------|
| `COMPOSE_FILE` | The compose files of this install: `docker-compose.yml` plus `docker-compose.prod.yml` (production) or `docker-compose.ports.yml` (development), plus `docker-compose.waf.yml` with the WAF on. Plain `docker compose` commands and `./opbx.sh` use the same files |
| `COMPOSE_PROFILES` | `logs` when Grafana logs are on; `dev` (ngrok) on a development install with an ngrok token |
| `COMPOSE_PARALLEL_LIMIT` | `2`. Parallel image builds can hang under Podman |
| `OPBX_INSTALLER_MANAGED` | `true`. The `admin@example.com` demo owner is never seeded, and `./install.sh reconfigure` may change this `.env` |
| `OPBX_OWNER_EMAIL` | The owner's email, used when an interrupted install is resumed |
| `OPBX_FRONT_PAGE` | `login` or `home` |
| `TRUSTED_PROXY_CIDR` | Your proxy's address (production) |
| `WAF_MODE`, `WAF_CONSOLE_ENABLED`, `WAF_CONSOLE_PORT`, `WAF_CONSOLE_BIND`, `WAF_CONSOLE_ALLOW` | The WAF settings |

### Change settings later

```bash
./install.sh reconfigure
```

**What would you like to change?** offers:

| Choice | Effect |
|--------|--------|
| **Change the public address** | Production only. Rewrites the address values in `.env`, rebuilds the frontend, restarts the stack and prints new proxy settings. On a server for just your company, save the Cloudonix connection again in **Settings** afterwards, which pushes the new webhook address to Cloudonix |
| **Change the front page** | Switches between the sign-in page and the OPBX homepage. Reload the browser to see it; nothing restarts |
| **Change the host names allowed to open OPBX** | Development only. Restarts the frontend (and Grafana) |
| **Turn the firewall on** | Asks the WAF questions, shows the data-folder commands, starts SafeLine and prints the WAF admin login |
| **Change the firewall mode**, **Change who can open the firewall console**, **Turn the firewall off** | Shown while the WAF is on. Turning it off keeps the firewall's data folder and offers to stop the SafeLine containers |

`reconfigure` refuses a `.env` that the installer did not write ("Cannot change settings here"). For a manual install, edit `.env` and run `./opbx.sh restart`.

### Start over

```bash
./install.sh reset
```

`reset` lists what it will destroy, offers a database backup into `./backups/`, and asks you to type the domain (production) or `RESET` (development). It then deletes `volumes/mysql`, `volumes/redis`, `volumes/seaweedfs`, `volumes/amd-dumps`, the Loki and Grafana volumes, the SafeLine `resources/` and `logs/` folders (a host step it shows you) and the generated configuration files. Afterwards it offers to install again with your previous answers.

:::danger
`./install.sh reset` deletes all call records, recordings, users and settings. Take the backup it offers.
:::

## Front Page

`OPBX_FRONT_PAGE` decides what the site root (`/`) shows:

| Value | `/` shows |
|-------|-----------|
| `login` | The sign-in page, or the dashboard when the visitor is already signed in |
| `home` (or unset) | The public OPBX homepage |

The installer asks and defaults to `login`. `.env.example` ships `home`, so a manual install shows the homepage until you change it. The app reads the value on every request: no restart or rebuild is needed. The sign-in page itself is always at `/ui/login`.

## SafeLine WAF

OPBX can put the [SafeLine](https://waf.chaitin.com/) community web application firewall in front of the web app. It is off by default; turn it on with the installer or `./install.sh reconfigure`.

| Mode | Behaviour |
|------|-----------|
| **Monitor only** (`WAF_MODE=monitor`) | Every request is checked; an attack is logged as "would block" in the Nginx error log and in the SafeLine console, but not blocked. Start here |
| **Blocking** (`WAF_MODE=block`) | Attacks are refused with HTTP 403. Cloudonix callbacks (`/api/webhooks/…`, `/api/voice/…`, `/api/callbacks/…`) are only ever monitored, because a 403 would drop a live call |

How it works:

- SafeLine runs as its own Compose project (`safeline`, files in `docker/safeline/`), with its data in the folder you chose. `./opbx.sh start` starts it before OPBX, and `./opbx.sh stop` stops it after OPBX.
- The OPBX Nginx (an OpenResty image, from `docker-compose.waf.yml`) asks the SafeLine detector about each request. If the detector is slow or down, the request goes through (fail open).
- The SafeLine console is served by the OPBX Nginx on `WAF_CONSOLE_PORT` (default 9443). In production, when you gave a proxy address, the installer asks which IPs or networks may open the console and Nginx allows only those (`WAF_CONSOLE_ALLOW`); without a proxy address only SafeLine's own login protects it. On a development install it listens on `127.0.0.1` only, unless you let other computers open it (optionally limited to an IP list, for example Tailscale's `100.64.0.0/10`).
- The WAF admin login is shown once at the end of the install and saved in the summary file. To set a new one: `docker exec safeline-mgt /app/mgt reset-admin`.
- `./opbx.sh start --no-waf` runs one start without the WAF, without changing `.env`.

Once the monitor-only logs look clean, switch to blocking with `./install.sh reconfigure`.

## Manual Setup

Use this only if you do not want the installer. It starts the stack with the default (development) compose file.

### 1. Clone the Repository

```bash
git clone https://github.com/greenfieldtech-nirs/opbx.git
cd opbx
```

### 2. Create the Configuration Files

```bash
cp .env.example .env
cp docker-compose.yml.example docker-compose.yml
```

`docker-compose.yml` is ignored by git, so you can adapt it to your host.

### 3. Set the Secrets

Fill in the shared secrets the workers, Soketi and Grafana need. The script writes only values that are missing or still a placeholder, and prints no values:

```bash
docker/scripts/generate-secrets.sh
```

It sets `DIALER_WORKER_API_TOKEN`, `AMD_WORKER_API_TOKEN`, `ACD_WORKER_API_TOKEN`, `PUSHER_APP_SECRET`, `GRAFANA_ADMIN_PASSWORD`, `MINIO_ACCESS_KEY` and `MINIO_SECRET_KEY`.

Then edit `.env` and set the rest by hand:

| Variable | Description | How to Generate |
|----------|-------------|-----------------|
| `APP_KEY` | Laravel encryption key | `echo "base64:$(openssl rand -base64 32)"` |
| `APP_URL` | Your public URL | `http://localhost` for local use |
| `DB_PASSWORD` | MySQL `opbx` user password | `openssl rand -base64 32` |
| `DB_ROOT_PASSWORD` | MySQL root password | `openssl rand -base64 32` |
| `REDIS_PASSWORD` | Redis password | `openssl rand -base64 32` |

The `.env.example` ships the S3 keys empty (the script above generates them). Compose itself refuses to start the stack (any service, any profile) while the worker tokens, `PUSHER_APP_SECRET`, the S3 keys or `GRAFANA_ADMIN_PASSWORD` are unset.

The `app` container checks the values again on every start and exits when one fails:

| Check | Fails when |
|-------|-----------|
| Weak passwords | `DB_PASSWORD`, `MINIO_ACCESS_KEY` or `MINIO_SECRET_KEY` is exactly `secret`, `password`, `rootsecret`, `minioadmin`, `admin` or `123456` |
| Required secrets | `APP_KEY`, `DB_PASSWORD`, `PUSHER_APP_SECRET`, `DIALER_WORKER_API_TOKEN`, `AMD_WORKER_API_TOKEN` or `ACD_WORKER_API_TOKEN` is empty, is `admin`, or **contains** a placeholder word: `CHANGE_ME`, `GENERATE_32_CHAR`, `64_CHAR_SECRET`, `default123`, `password`, `secret`, `change-in-production` or `pbxappsecret` |
| Grafana | Same rule for `GRAFANA_ADMIN_PASSWORD`, only when the log stack is enabled (`LOG_STACK_ENABLED=true` or `logs` in `COMPOSE_PROFILES`) |
| Password length | `DB_PASSWORD` is shorter than 8 characters |
| Production | `APP_ENV=production` with `APP_DEBUG=true`, or with `REDIS_EXPOSE_PORT` set |

`DB_ROOT_PASSWORD` is not checked (MySQL falls back to `rootsecret` when it is unset), so make sure you set it. Because the check looks for the words inside the value, a generated secret must not contain `password` or `secret`. Values from `openssl rand` never do.

Optional but commonly configured variables:

| Variable | Description | Default |
|----------|-------------|---------|
| `APP_PORT` | Host port for Nginx | `80` |
| `FRONTEND_PORT` | Host port for the Vite dev server | `3000` |
| `OPBX_FRONT_PAGE` | What the site root shows: `home` or `login` (see [Front page](#front-page)) | `home` |
| `NGROK_AUTHTOKEN` | ngrok authtoken for local webhook development | *(empty)* |
| `NGROK_DOMAIN` | Custom ngrok domain (paid plans) | *(empty)* |
| `USERCHECK_API_TOKEN` | UserCheck email validation token | *(empty)* |
| `DB_CDR_ARCHIVE_DATABASE` | Separate schema for the warm call-record archive. Create it and grant the app user first | *(main schema)* |

All variables are listed in the [Configuration Reference](/opbx/data-models/configuration/index).

:::note Cloudonix Configuration
Cloudonix credentials are per organization and are entered in the web UI after your first login. Do not add them to `.env`.
:::

:::danger Security Notice
Never commit `.env` or `docker-compose.yml` to version control.
:::

### 4. Install the PHP Dependencies

The compose file bind-mounts the repository over the app image, so the `vendor/` directory must exist on the host. The app container stops with "Composer dependencies are not installed" when it is missing. Install them inside the app image (no PHP needed on the host):

```bash
docker compose run --rm --no-deps --user "$(id -u):$(id -g)" -e COMPOSER_HOME=/tmp/composer \
  --entrypoint composer app install --no-interaction --prefer-dist --optimize-autoloader
```

`--user` keeps `vendor/` owned by you. Add `--no-dev` for production. `./opbx.sh upgrade` runs this step for you on later upgrades.

### 5. Start the Services

```bash
./opbx.sh start
```

This builds any missing images, starts the database, Redis, SeaweedFS and `app` first, waits for `app` to be healthy, starts the rest and waits until every service is up. A plain `docker compose up -d` also works. These services start:

| Service | Container | Purpose | Host Port |
|---------|-----------|---------|-----------|
| `app` | `opbx_app` | Laravel PHP-FPM backend | — |
| `nginx` | `opbx_nginx` | Reverse proxy | `APP_PORT` (80) |
| `frontend` | `opbx_frontend` | React Vite dev server | `FRONTEND_PORT` (3000) |
| `mysql` | `opbx_mysql` | MySQL 8.4 LTS | — |
| `redis` | `opbx_redis` | Cache, sessions, queues, locks | — |
| `seaweedfs` | `opbx_seaweedfs` | S3-compatible object storage | — |
| `soketi` | `opbx_websocket` | WebSocket server | 6001, 9601 |
| `queue-worker` | `opbx_queue_worker` | Laravel queue worker | — |
| `queue-worker-long` | `opbx_queue_worker_long` | Queue worker for long jobs (distribution list uploads, queue hold-music segmentation) | — |
| `scheduler` | `opbx_scheduler` | Laravel scheduler | — |
| `dialer-worker` | `opbx_dialer_worker` | Go auto-dialer worker (one replica) | — |
| `amd-worker` | `opbx_amd_worker` | Java/Vert.x answering-machine detection | — |
| `acd-worker` | `opbx_acd_worker` | Java/Vert.x call queue engine | — |
| `mcp-server` | `opbx_mcp` | MCP server for AI agents (see [MCP Server](/opbx/modules/mcp-server)) | — |

Two groups of services start only with a profile:

| Profile | Services | Start with |
|---------|----------|------------|
| `dev` | `ngrok` (webhook tunnel) | `./opbx.sh start --with-ngrok`, or `docker compose --profile dev up -d ngrok` |
| `logs` | `loki`, `alloy`, `grafana`, `docker-socket-proxy` | Add `logs` to `COMPOSE_PROFILES` in `.env`, or `docker compose --profile logs up -d` (see [Centralized Logs](/opbx/administration/centralized-logs)) |

:::tip First Boot
On start, the `app` container validates the environment, waits for MySQL (up to `MYSQL_WAIT_TIMEOUT`, default 60 seconds), runs migrations, seeds a fresh database, checks object storage and validates the configuration. Wait **120 seconds** after starting the containers before testing.
:::

### 6. Storage Buckets

The app expects two private buckets in SeaweedFS: `recordings` (call recordings, IVR audio) and `cdr-archive` (cold call-record archive). On every start, `app` waits for SeaweedFS (up to `STORAGE_WAIT_TIMEOUT`, default 120 seconds), creates either bucket if it is missing and checks that both are writable. Nothing to do by hand; to create them yourself, see `docker/README.md`.

### 7. Verify the Installation

```bash
./opbx.sh status
```

It lists every service with its state and health (`docker compose ps` shows the same) and ends with "All services are up" when everything is running. Every service with a healthcheck should show `healthy`. The `app`, `mysql`, `redis`, `seaweedfs`, `soketi`, queue workers, `scheduler`, the three workers and `mcp-server` all have one.

Test the public health endpoint:

```bash
curl http://localhost/api/health
```

```json
{
  "status": "ok",
  "timestamp": "2026-06-22T12:00:00+00:00"
}
```

### 8. Access the Application

| URL | Purpose |
|-----|---------|
| `http://localhost/ui/login` | OPBX web application |
| `http://localhost/` | The public homepage, or the sign-in page with `OPBX_FRONT_PAGE=login` |
| `http://localhost/status` | Public platform status page |
| `http://localhost/api/health` | Public health check |
| `http://localhost:4040` | ngrok dashboard (while ngrok runs) |
| `http://localhost/logs/` | Grafana log viewer (`logs` profile) |

A fresh database is seeded with a default organization and an owner account (`admin@example.com` / `password`) whose password you must change. Go on to [First Login](/opbx/installation/first-login).

## Starting and Stopping

`./opbx.sh` (in the repository root) starts and stops the stack in the right order:

```bash
./opbx.sh start               # SafeLine first when the WAF is on, then the database, Redis, storage and app, then the rest
./opbx.sh start --no-waf      # this run without the WAF; .env is not changed, the next start brings it back
./opbx.sh start --nofork      # stay in the foreground with every service's log; Ctrl-C stops the stack
./opbx.sh start --with-ngrok  # this run also starts the ngrok tunnel for webhook development (needs NGROK_AUTHTOKEN)
./opbx.sh stop                # stops OPBX (every profile), then SafeLine; containers, network and data are kept
./opbx.sh restart             # stop + start (takes the same options as start)
./opbx.sh status              # state and health of every service, SafeLine, the WAF mode, the URLs
./opbx.sh logs [service...]   # follow the logs (all services, or the ones named)
./opbx.sh upgrade             # after git pull (see Updating OPBX)
./opbx.sh --help              # all commands and options
```

`start` waits up to 5 minutes for every service (`START_TIMEOUT`, in seconds), names any service that did not come up, and prints the URLs (web app, WAF console, Grafana, ngrok). With `--nofork`, Ctrl-C stops OPBX and then SafeLine, the same way `./opbx.sh stop` does.

`--with-ngrok` is for one run. On a development install where you gave the installer an ngrok token, `COMPOSE_PROFILES` already contains `dev` and every `start` runs ngrok.

`--prod` is only for a hand-made `.env` without `COMPOSE_FILE`: it adds `docker-compose.prod.yml`. An installer-made `.env` lists its compose files in `COMPOSE_FILE`, which always wins.

`stop` uses `docker compose stop`, never `down`: `down` deletes the Docker network, and recreating it has been seen to leave a stale host firewall rule that silently drops traffic to a container. To remove everything and start over, use `./install.sh reset`.

To understand how calls are handled, see the [Call Routing Overview](/opbx/installation/call-routing-overview) and [Outbound Calling Overview](/opbx/installation/outbound-calling-overview).

## Troubleshooting

### The Installer Does Not Start

| Message | Fix |
|---------|-----|
| `run ./install.sh in an interactive terminal` | Run it in a terminal, not from a script or a pipe |
| `'docker version' failed: is the Docker/Podman daemon running?` | Start Docker Desktop, the Docker service or the Podman machine |
| `'docker compose' is not available` | Install the Docker Compose plugin |
| `cannot reach the container daemon socket … from inside a container` | The installer mounts the daemon socket into its container. Check that the socket exists where the daemon reports it (Podman: `docker info`) |
| `Not enough free disk space` | Free at least 10 GB in the repository's file system |

Set `OPBX_DEBUG=1` before `./install.sh` to print the full error when the installer fails. After a failure, run `./install.sh` again: it resumes.

### Port Conflicts

Change the corresponding variable in `.env`:

```bash
APP_PORT=8080        # Nginx on 8080 instead of 80
FRONTEND_PORT=3001   # Vite on 3001 instead of 3000
```

### The app Container Exits on Start

```bash
./opbx.sh logs app
```

Common causes: an empty or placeholder secret, a weak database password or S3 key, `APP_DEBUG=true` in production, a missing `vendor/` directory ("Composer dependencies are not installed"), or MySQL not ready within `MYSQL_WAIT_TIMEOUT` seconds ("MySQL not ready after …"). The log names the variable that failed.

### SafeLine Does Not Come Up

`./opbx.sh start` stops with "SafeLine did not come up" when the detector is not healthy within 5 minutes. Check `docker logs safeline-detector` and that the firewall's data folder still exists. "docker/safeline/.env is missing" means the WAF is on in `.env` but SafeLine was never set up: run `./install.sh reconfigure`. To run without the WAF meanwhile, use `./opbx.sh start --no-waf`.

### "No such image" Errors (podman-compose)

Podman-compose does not build images automatically. Build them first:

```bash
docker compose build   # or: docker compose build mcp-server
docker compose up -d
```

`docker compose up -d --build` also works.

### MySQL Slow Start

MySQL may take longer to initialize on first boot:

```bash
./opbx.sh logs mysql
```

### Permission Denied

Make sure your user is in the `docker` group:

```bash
sudo usermod -aG docker $USER
# Log out and back in for changes to take effect
```

### Container Failures

```bash
./opbx.sh logs [service-name]
```

Common service names: `app`, `nginx`, `mysql`, `redis`, `seaweedfs`, `queue-worker`, `scheduler`, `dialer-worker`, `amd-worker`, `acd-worker`, `mcp-server`.

### Migrations Do Not Run

The `app` container runs migrations unless `RUN_MIGRATIONS=false`. The queue workers and scheduler never run them. To run them by hand:

```bash
docker compose exec app php artisan migrate
```

### Webhooks Not Received in Local Development

For Cloudonix to reach your local instance, run the ngrok tunnel:

1. Add `NGROK_AUTHTOKEN` to `.env` (the installer does this when you give it an ngrok token).
2. Start the stack with the tunnel: `./opbx.sh start --with-ngrok`. With the installer's ngrok token, a plain `./opbx.sh start` already runs it.
3. Find your public HTTPS URL in the ngrok dashboard (`http://localhost:4040`) or with `./opbx.sh logs ngrok`.
4. Sign in as the Owner, open **Settings** from the user menu (top right), enter that URL in **Webhook Base URL** and click **Validate and Save Settings**.

If you open OPBX through the ngrok domain, add that domain to the allowed host names (`./install.sh reconfigure`, or `VITE_ALLOWED_HOSTS` in `.env`).

## Updating OPBX

```bash
# Pull the new version
git pull

# Bring docker-compose.yml up to date with docker-compose.yml.example
./scripts/update-compose.sh --dry-run   # report only
./scripts/update-compose.sh             # asks per changed service

# Rebuild, install the PHP packages and start in order
./opbx.sh upgrade             # same as ./scripts/upgrade.sh; add --prod only for a hand-made .env without COMPOSE_FILE
```

`./opbx.sh upgrade` needs only Docker on the host. It starts the stack in the right order and shows progress instead of failing:

1. If `./volumes/minio` still holds data from an older installation, it runs `./scripts/migrate-minio-to-seaweedfs.sh` once (see below). With many recordings this takes a while.
2. It builds every image, pulling fresh base images (so a security release of PHP or another base image is picked up).
3. It runs `composer install` inside the app image as your user (`--no-dev` when `APP_ENV=production`) and refreshes Laravel's package cache.
4. It starts SafeLine first when the WAF is on, then MySQL, Redis, SeaweedFS and `app`, and shows the `app` log (database migrations, seeding, bucket creation) until the container is healthy. The first start after an upgrade can take several minutes; that is expected.
5. It starts the rest of the stack and waits until every service is up.

It uses the compose files listed in `.env` (`COMPOSE_FILE`, written by the installer), so the WAF and development port settings are kept. `--no-waf` upgrades without starting the WAF.

It stops with an error only if `app` exits, turns unhealthy, or is not ready after 30 minutes (`UPGRADE_TIMEOUT`, in seconds). A plain `docker compose up -d` also works: nginx, the queue workers and the scheduler wait while `app` is still starting (its health check allows up to 15 minutes for the first start); follow it with `docker compose logs -f app`.

On every start `app` waits up to 2 minutes for SeaweedFS (`STORAGE_WAIT_TIMEOUT`, in seconds) and creates the `recordings` and `cdr-archive` buckets if they are missing.

`scripts/update-compose.sh` compares your `docker-compose.yml` with the new example service by service (all profiles). New services are added, services that exist only in your file are kept, and services removed upstream (such as `minio`) are removed only when you confirm. It validates the result with `docker compose config`, keeps the old file as `docker-compose.yml.bak-<timestamp>`, and restarts nothing. `--yes` runs it unattended. It needs only Docker.

### Upgrading from MinIO

Older installations stored objects in MinIO (`./volumes/minio`). SeaweedFS replaces it. After updating `docker-compose.yml`, copy the objects across:

```bash
./scripts/migrate-minio-to-seaweedfs.sh --dry-run   # list buckets and object counts
./scripts/migrate-minio-to-seaweedfs.sh             # copy and verify every bucket
```

`./opbx.sh upgrade` runs this for you the first time (and records it in `./volumes/.minio-migrated-to-seaweedfs`); run it by hand only to check first or to re-run. The script starts SeaweedFS and a temporary MinIO container on the old data, mirrors every bucket, verifies it, and leaves `./volumes/minio` in place as a fallback. It is safe to re-run. When it succeeds, make sure `.env` has `MINIO_ENDPOINT=http://seaweedfs:8333` and start the stack (`./opbx.sh upgrade`). A bucket that MinIO never had (for example `cdr-archive`) is created when `app` starts. Copied objects get a new modification date, so recording retention counts from the migration date.

### Upgrading from MySQL 8.0

The compose file uses MySQL 8.4. Back up first (`./scripts/backup-database.sh`); an 8.0 data directory is upgraded in place on the first 8.4 start. `docker/mysql/my.cnf` keeps `mysql_native_password` loaded for older clients.

:::warning Data Preservation
MySQL, Redis and SeaweedFS data live in bind mounts under `./volumes/` (`mysql`, `redis`, `seaweedfs`). They survive `docker compose down` and `down -v`. Deleting the `volumes/` directory deletes the data. The `logs` profile keeps Loki and Grafana data in the named volumes `loki_data` and `grafana_data`, which `down -v` does remove.
:::

## Production Deployment

The installer sets up production for you (choose **Production**). By hand, serve the compiled frontend instead of the Vite dev server with the production overlay:

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

or `./opbx.sh start --prod`. `docker-compose.prod.yml` builds the frontend as a static site (the `VITE_*` values are baked in at build time; set `VITE_WS_HOST`, `VITE_WS_PORT` and `VITE_WS_SCHEME` for your public host), removes the dev ports and bind mounts, and switches Nginx to the production virtual host in `docker/nginx/conf.d.prod`.

Also:

1. Terminate TLS in front of Nginx (a load balancer or another reverse proxy), and set `TRUSTED_PROXY_CIDR` to its address.
2. Back up MySQL (`./scripts/backup-database.sh`) and `./volumes/seaweedfs` on a schedule.
3. Set `APP_ENV=production` and `APP_DEBUG=false`.
4. For a server that hosts many organizations, set `OPBX_APPLICATION_MODE=production` and `OPBX_APPLICATION_WEBHOOK_BASEURL` to your public URL.
5. Restrict `SANCTUM_STATEFUL_DOMAINS` to your domains.
6. Rotate the worker tokens regularly.
7. Optionally enable the [log stack](/opbx/administration/centralized-logs) and the [SafeLine WAF](#safeline-waf).

:::danger Security Notice
Never expose the MySQL, Redis or SeaweedFS ports to the internet, and never use `docker-compose.ports.yml` on a production host.
:::
