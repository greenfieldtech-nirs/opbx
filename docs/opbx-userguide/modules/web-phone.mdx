# Web Phone

The Web Phone is a softphone built into OPBX. It registers your own **user extension** with Cloudonix over WebRTC, so you can place and receive calls in the browser without a desk phone or a SIP app. Owners and Supervisors also use it to coach live calls.

## Purpose

Use the Web Phone to:

- place calls from any page of OPBX;
- answer calls to your extension in the browser, whether or not the panel is open;
- redial your recent outbound calls;
- spy, whisper or barge from [Live Calls](/opbx/modules/live-calls) (Owners and Supervisors).

The same Web Phone can be placed on another website, such as a CRM. See [Embedded Dialer](/opbx/modules/embedded-dialer).

## Prerequisites

- A **user extension** assigned to you (extension type User). Other extension types, such as forward or ring group extensions, do not count. See [Extensions](/opbx/modules/extensions).
- The organization's Cloudonix settings, with a domain name. See [Settings](/opbx/modules/settings).
- A browser with microphone access. The browser asks for permission the first time you place or answer a call.
- Network access to `wss://webrtc.cloudonix.io` on port 443.

## Availability

| Role | Use the Web Phone | Coach calls with it |
|------|:-----------------:|:-------------------:|
| Owner | Yes, with a user extension | Yes |
| PBX Admin | Yes, with a user extension | No |
| PBX User | Yes, with a user extension | No |
| Reporter | Yes, with a user extension | No |
| Supervisor | Yes, with a user extension | Yes, calls in their scope |

The role does not decide whether the Web Phone works; the extension does. Without a user extension the Web Phone opens with **Web Phone Unavailable** — "No extension is assigned to your account. Web Phone cannot be used."

:::note
When the organization has no Cloudonix domain configured, the panel instead says "Cloudonix isn't configured for your organization" and asks you to have your Owner complete Settings > Cloudonix (the server answers 409 `cloudonix_not_configured`, while a missing extension is 404).
:::

## Workflows

No role check applies to these tasks; the Web Phone only needs your user extension.

### Open the Web Phone

Who can do this: any user with a user extension.

1. Click the round phone button in the bottom-right corner of any page (tooltip **Web Phone**).
2. The panel opens. Under **Web Phone**, the header shows a registration badge: amber **Registering…** while it connects, then green **Registered**.
3. When the badge reads **Registered**, the **Keypad** tab is ready.

The badge always shows what Cloudonix last confirmed:

| Badge | Meaning |
|-------|---------|
| Green **Registered** | Cloudonix accepted the registration; calls to your extension reach this browser. |
| Amber **Registering…** | The phone is connecting or registering. |
| Red **Not registered** | Cloudonix no longer holds the registration (it was refused or lost). Incoming calls do not reach you. |
| Red **Disconnected** | The connection to Cloudonix dropped. The phone reconnects and registers again by itself. |

The first time you open the Web Phone, the browser asks whether OPBX may show notifications. Allow it to be alerted to incoming calls while you work in another tab or application (see [Answer an incoming call](#answer-an-incoming-call)). You can change this later in the browser's site settings.

Close the panel with **X**. While a call is ringing or active, **X** is disabled ("End the call before closing").

:::note The phone stays registered
The Web Phone registers when you sign in to OPBX and stays registered while you are signed in, whether the panel is open or not. An incoming call opens the panel and rings. Closing the panel does not unregister the phone; signing out does.
:::

### Re-register the phone

Who can do this: any user with a user extension.

Use this when you suspect calls are not reaching you, or the badge is red.

1. Open the Web Phone.
2. Click the circular-arrow button next to the badge (tooltip **Re-register**).

The badge turns amber **Registering…** while the Web Phone drops its registration and registers again, then green **Registered** once Cloudonix accepts it. If the connection to Cloudonix is gone, the Web Phone reconnects first. If Cloudonix refuses the registration, the panel shows the error (see [Common errors](#common-errors)). The button is disabled during a call.

### Place a call

Who can do this: any user with a user extension.

1. [Open the Web Phone](#open-the-web-phone).
2. On the **Keypad** tab, type the number or click the keys (`0`–`9`, `*`, `#`). Use the backspace button to correct. A number is dialled at your Cloudonix domain; an entry that contains `@` is dialled as that SIP address.
3. Click the green call button, or press **Enter** in the number field. The green button stays disabled while the number is empty.
4. The status reads "Calling..." and then "Ringing...", and you hear the ringing tone of your country (see [Call-progress tones](#call-progress-tones)). Click the red button to cancel.
5. When the call connects, the status reads "On call" and a timer starts: `M:SS`, then `H:MM:SS` after one hour.
6. Hang up with the red button.

The panel returns to the keypad. If the call fails because the other side is busy or the network is congested, the matching tone plays.

While a call is ringing or active, the rest of the page is dimmed and blocked, the panel cannot be closed, and the **Keypad** / **Recents** tab bar is locked. The keypad is not shown once the call connects, so you cannot send touch tones (DTMF) from the Web Phone. Transferring a call is not available in the Web Phone.

### Answer an incoming call

Who can do this: any user with a user extension.

1. While the phone is registered, an incoming call opens the panel by itself, rings with your country's ringing tone, and shows **Incoming call** with the caller: their name and number when the call carries a name (for example `Alice (1001)`), otherwise the number.
2. Click the green **Answer** button. The ringing stops. The browser asks for microphone access the first time.

The call controls appear (see [Use the call controls](#use-the-call-controls)) and the timer starts. The ringing also stops if the caller hangs up first.

While the call rings, the browser tab title alternates with "Incoming call: …". If you are in another tab or application and allowed notifications, the browser also shows an **Incoming call** notification with the caller. Click it to bring OPBX to the front with the Web Phone open, then click **Answer**.

If a call comes in while you are already on a call (or another call is ringing), the Web Phone answers it as busy, so the call continues to the next step of its routing, such as other ring group members or voicemail.

{/* SCREENSHOT: web-phone-incoming — Web Phone panel showing "Incoming call" with a caller such as Alice (+12025550142) and the green Answer and red Reject buttons */}

### Reject an incoming call

Who can do this: any user with a user extension.

1. When the panel shows **Incoming call**, click the red **Reject** button.

The ringing stops, the call is ended and the panel returns to the keypad.

### Use the call controls

Who can do this: any user with a user extension.

During a connected call the panel shows the call's Cloudonix session token at the very top (select it to copy it, for example when reporting a call problem; it appears a moment after the call connects), then the timer and the number (for an incoming call, the caller ID with the caller's name below it in larger type, or the caller ID alone when the call carries no name), **Mute**, **Keypad**, **Hold** and **Transfer** in one row above the red hang-up button at the bottom, and the volume buttons on the right edge:

| Control | What it does |
|---------|--------------|
| **Mute** / **Unmute** | Stops or resumes sending your microphone |
| **Keypad** | Shows or hides the in-call keypad for sending tones (see below) |
| **Hold** / **Resume** | Puts the other party on hold |
| **Transfer** | Sends the other party to another extension or number (see [Transfer a call](#transfer-a-call)) |
| **+** / **−** (right edge) | Raise or lower the incoming audio in 10% steps; the bar between them shows the level |
| Hang up (red, bottom) | Ends the call |

1. Click **Mute** to stop sending your microphone; the button turns blue and reads **Unmute**. Click it again to resume.
2. Click **Hold** to put the other party on hold; the button reads **Resume**. Click it again to take the call off hold.
3. Click **+** or **−** to change the incoming audio level. Lowering it all the way silences the other party.
4. Click the red button to hang up.

{/* SCREENSHOT: web-phone-in-call — Web Phone during a connected call with the timer, Mute, Keypad and Hold in a row above the red Hang Up button, the + / − volume buttons with the level bar on the right edge, and the page behind dimmed */}

### Send tones during a call

Who can do this: any user with a user extension.

Use the in-call keypad to answer a voice menu ("press 1 for sales"), enter a conference PIN or type an account number.

1. During a connected call, click **Keypad**. The button turns blue and the keypad opens above the call controls.
2. Click a key (`0`–`9`, `*`, `#`), or type it on your keyboard. Each key sends one tone to the other party and plays a short beep for you.
3. The keys you sent appear under the call timer.
4. Click **Keypad** again to hide the keypad. The keys you sent are cleared when the call ends.

{/* SCREENSHOT: web-phone-in-call-keypad — Web Phone during a connected call with the keypad open, a few sent digits under the timer, and Keypad highlighted in the call controls */}

### Redial a recent call

Who can do this: any user with a user extension.

1. [Open the Web Phone](#open-the-web-phone).
2. Click the **Recents** tab.
3. Click the row of the number you want to call.

The Web Phone switches to **Keypad**, fills in the number and places the call.

The **Recents** tab lists the last **50** calls placed **from your extension**, newest first. Each row shows the number, when it was placed and, for calls with a duration, how long it lasted. The icon is green when the disposition is `ANSWER` or `CONNECTED` and red otherwise.

- The list is reloaded each time you open the tab ("Loading recent calls...").
- Coaching calls are left out.
- Only your own extension's calls are shown, never another user's.

When there are none, the tab reads "No recent calls yet." If the list cannot be loaded, it reads "Could not load recent calls."

{/* SCREENSHOT: web-phone-recents — Web Phone Recents tab listing several recent outbound calls with time, duration and coloured dispositions */}

### Change the Web Phone settings

Who can do this: any user with a user extension.

1. [Open the Web Phone](#open-the-web-phone).
2. Click the **Settings** tab.
3. Turn the settings on or off. **Save** becomes available once something has changed.
4. Click **Save**.

| Setting | Default | What it does |
|---------|---------|--------------|
| **Auto-Answer** | Off | Answers an incoming call once it has rung for 2 seconds. A call that arrives while you are already on a call is still answered busy, so Auto-Answer only ever picks up a call when the phone is free. |
| **Keep-Alive** | On | Registers the phone again every 60 seconds, so a dropped registration comes back within a minute. |
| **Refresh on hangup** | On | Registers the phone again after each call ends. |

The settings are stored in your extension's Cloudonix subscriber profile, so they follow your extension to every browser, and they apply at once, without reloading. When the Web Phone starts and the profile has no settings yet, OPBX stores the defaults there. Other values in the profile are kept.

If Cloudonix does not accept the settings, the tab shows the reason (for example "Cloudonix did not accept the settings. Try again shortly.") and keeps your changes so you can save again. An extension that is not synced to Cloudonix yet cannot store settings: "This extension is not synced to Cloudonix yet, so its settings cannot be stored."

The [Embedded Dialer](/opbx/modules/embedded-dialer) applies the same settings but has no **Settings** tab.

{/* SCREENSHOT: web-phone-settings — Web Phone Settings tab with the three switches and the Save button */}

### Move the Web Phone to this tab

Who can do this: any user with a user extension.

Only one browser tab holds the registration. In any other tab the panel says "Web Phone is active in another tab".

1. Open the Web Phone in the tab you want to use.
2. Click **Use here**.

This tab takes the registration and the other tab shows "Web Phone is active in another tab". When the tab holding the registration closes, the next open tab takes over automatically.

### Retry after an error

Who can do this: any user with a user extension.

1. When the panel shows an error (see [Common errors](#common-errors)), click **Retry**.

The Web Phone loads its configuration again (for configuration errors) or starts a new registration (for registration errors), and the badge goes back to **Registering…**. **Web Phone Unavailable — No extension is assigned to your account** has no **Retry** button: assign a user extension and reload the page.

### Transfer a call

Who can do this: any user with a user extension. In the [Embedded Dialer](/opbx/modules/embedded-dialer), only when the user's snippet allows call transfer.

Transfer hands the other party to another extension or an outside number and takes you off the call (a blind transfer: you do not speak to the new party first).

1. During a connected call, click **Transfer**. The button turns blue and a **Transfer to** field opens.
2. Type an extension or a phone number. As you type, up to four of your organization's extensions appear below the field, matched by number or by the user's name; click one to fill the field.
3. Click **Transfer**.

The other party is sent on, your side of the call ends, and the keypad shows "Call transferred to `<destination>`". **Cancel** closes the field and leaves the call as it was.

The transfer routes the destination exactly as if you had dialled it from your extension:

- **An extension** rings as a normal call to it, including its forwarding and voicemail. The new party sees the original caller's number.
- **An outside number** must be allowed by your organization's [outbound whitelist](/opbx/modules/outbound-whitelist), and the new party sees the caller ID your extension uses for its own outbound calls.

Transfer works for calls you placed, calls to your extension, and calls you took from a ring group or a call queue. A transferred queue call counts as answered by you; its handling time ends at the transfer and you become available for the next queue call (after wrap-up). Transfer is not offered on coaching calls.

If the transfer fails, the field shows why ("The transfer failed. The call is still connected.") and you stay on the call. You cannot transfer a call to your own extension.

## Coaching from Live Calls

When an Owner or Supervisor clicks **Spy**, **Whisper** or **Barge** on [Live Calls](/opbx/modules/live-calls), the Web Phone opens by itself and dials the coaching target. Once connected, the header reads "On call - Coaching: Spy" (or Whisper, Barge). When the coaching call ends, the Web Phone closes.

## Call-progress tones

The ringing, busy and congestion tones follow the conventions of the organization's country, taken from the organization's `country` setting (default `us`; it cannot be changed from the UI). The cadences come from the standard Asterisk indications table.

## Common errors

| Message | What it means | What to do |
|---------|---------------|-----------|
| Web Phone Unavailable — No extension is assigned to your account. Web Phone cannot be used. | No user extension | Assign a user extension, then reload the page |
| Web Phone Unavailable — Cloudonix isn't configured for your organization. | The organization has no Cloudonix domain | Ask your Owner to complete [Settings](/opbx/modules/settings) |
| Web Phone Unavailable — Could not load the Web Phone configuration from the server. | Any other failure of `GET /v1/webphone/config` | **Retry**; if it persists, contact your administrator |
| Web Phone Error — The Web Phone engine failed to load. | The bundled SIP library did not load | Reload the page |
| Connection Failed — Could not open a connection to the voice server. | The browser cannot reach `wss://webrtc.cloudonix.io` | Check the network and firewall, then **Retry** |
| Authentication Rejected | Cloudonix refused the extension's password | Reset the extension password on [Extensions](/opbx/modules/extensions) |
| Extension Not Found | The subscriber does not exist in Cloudonix | Check that the extension is synced to Cloudonix |
| Web Phone Error — …no reply came back in time. | Registration timed out | **Retry** in a moment |
| Web Phone Error — Registration with the voice server failed. | Any other registration failure | **Retry**; if it persists, contact your administrator |

Registration errors also show the raw cause from the SIP library (for example `Request Timeout`). Every error screen except the missing-extension one has a **Retry** button.

## How it works

1. When you sign in (in the tab that holds the registration), OPBX calls `GET /v1/webphone/config` for your extension's SIP settings.
2. The bundled JsSIP library (served by OPBX itself, not loaded from a third-party site) creates a SIP user agent.
3. The user agent connects to `wss://webrtc.cloudonix.io:443` and registers as `sip:<extension>@<your Cloudonix domain>` with the extension's password.
4. Calls you place go through the normal OPBX outbound routing, as from any other phone on your extension.

### Config response fields

| Field | Meaning |
|-------|---------|
| `sip_username`, `sip_contact` | Your extension number |
| `sip_password` | Your extension's SIP password |
| `sip_domain` | The organization's Cloudonix domain |
| `sip_uri` | `sip:{extension}@{domain}` |
| `display_name`, `profile_name` | Your name |
| `wss_server`, `websocket_port`, `server_path` | `wss://webrtc.cloudonix.io`, `443`, empty |
| `registration_mode` | `Direct` |
| `country` | Country code for tones |
| `settings` | `auto_answer`, `keep_alive`, `refresh_on_hangup` (booleans) from the subscriber profile; the defaults when Cloudonix cannot be reached |

The config contains your SIP password. It is returned only to you, for your own extension, and every request is logged as a security event.

## Related API endpoints

| Method | Endpoint | Purpose |
|--------|----------|---------|
| GET | `/v1/webphone/config` | SIP settings for the signed-in user. 404 "No extension is assigned to this user." when there is no user extension; 409 with `error: cloudonix_not_configured` when the organization has no Cloudonix domain |
| GET | `/v1/webphone/calls-log` | The last 50 calls placed from the user's extension |
| PUT | `/v1/webphone/settings` | Store `auto_answer`, `keep_alive` and `refresh_on_hangup` (all required booleans) in the extension's Cloudonix subscriber profile. 409 when the extension is not synced to Cloudonix; 502 when Cloudonix does not accept them |
| POST | `/v1/webphone/transfer` | Blind-transfer the user's call: `call_id` (the Web Phone's SIP Call-ID) and `destination` (extension or number, digits with an optional `+`). 404 when the call is not found or does not involve the user's extension; 422 for the user's own extension; 502 when Cloudonix refuses (the call stays connected) |
| GET | `/v1/webphone/session?call_id=` | The Cloudonix session token of the user's call, named by its SIP Call-ID; 404 until Cloudonix has reported the session |
| GET | `/v1/webphone/directory` | The organization's active user extensions other than the user's own, with the user's name, for transfer suggestions |
| POST | `/v1/session-updates/{sessionId}/coach-target` | Dial target for coaching |

These endpoints are for signed-in users only; scoped API keys cannot call them.

See the [OPBX REST API reference](https://developers.cloudonix.com/opbxRestOpenAPI) for full schemas.
