# Reporting and Analytics

OPBX has no single "Reports" page. Each kind of call data has its own page: the Dashboard, live views, call history, queue reports and campaign analytics. This page tells you which one to open for a given question, and who can see it.

## Purpose

Use this page to find:

- the report that answers your question;
- which roles can open it;
- which reports can be exported to CSV.

## Which report answers which question

| Question | Open | Sidebar section |
|----------|------|-----------------|
| What is happening right now, in numbers? | **Dashboard** | Dashboards |
| Which calls are up right now, and on which extension? | [Live Calls](/modules/live-calls) | Analytics |
| Who called whom, when, for how long, with what result? | [Call Logs](/modules/call-logs) | Analytics |
| How long are callers waiting in each queue, and which agents are free? | **Queues Dashboard** (see [Call Queues](/modules/call-queues#live-monitoring)) | Analytics |
| How did each queued call end (answered, abandoned, overflow)? | **Queue Reports** (see [Call Queues](/modules/call-queues#reporting)) | Analytics |
| Which marketing source brings calls and conversions? | Call Tracking **Dashboard** and **Sessions** (see [Call Tracking Analytics](/modules/call-tracking-analytics)) | Apps and Security |
| How is an outbound campaign progressing? | Auto Dialer **Real Time Monitor** (see [Real-Time Monitor](/applications/auto-dialer/real-time-monitor)) | Apps and Security |
| Were our call events delivered to our webhook? | **Call Notifications**, delivery log (see [Call Notifications](/modules/call-notifications)) | Analytics |
| How often was a blocked caller turned away? | **Inbound Blacklist**, Blocked Count column (see [Inbound Blacklist](/modules/inbound-blacklist)) | Apps and Security |

## Who can see what

| Report | Owner | PBX Admin | PBX User | Reporter | Supervisor |
|--------|:-----:|:---------:|:--------:|:--------:|:----------:|
| Dashboard | Organization | Organization | Organization | Organization | Assigned scope |
| Live Calls | Yes | Yes | No | Yes, read-only | Assigned scope |
| Call Logs | Yes | Yes | Yes, read-only | Yes, read-only | Assigned scope, read-only |
| Call Logs CSV export (button) | Yes | Yes | No | No | No |
| Queues Dashboard, Queue Reports | Yes | Yes | No | Yes | No |
| Call Tracking Dashboard and Sessions | Yes | Yes | Yes | Yes | No |
| Auto Dialer Real Time Monitor | Yes | Yes | No | No | No |
| Call Notifications delivery log | Yes | Yes | No | No | No |
| Inbound Blacklist counts | Yes | Yes | No | No | No |

"Assigned scope" means calls to or from the users and ring groups assigned to the Supervisor. See [Supervisors](/modules/supervisors).

The table shows what each role reaches through the sidebar. Several of these endpoints are readable by more roles through the API; the module pages describe the exact server rules.

## The Dashboard

Every role lands on the Dashboard after signing in.

For Owners, PBX Admins, PBX Users and Reporters it shows:

- **Active Calls**, **Extensions**, **Phone Numbers** and **Conference Rooms** counters;
- **Last Calls**: the most recent call records, with time, from, to, status and duration.

The active-call counter refreshes every 15 seconds and the other cards every 30 seconds, only while the browser tab is visible.

Supervisors see their own variant with assigned users, assigned ring groups, active calls in scope and the last 5 calls in scope. See [Supervisors](/modules/supervisors#the-supervisors-dashboard).

## Exporting data

| Data | How to export | Format |
|------|---------------|--------|
| Call records | Call Logs → apply filters → **Export** | CSV, produced in chunks of 1000 rows |
| Queue calls | Queue Reports → apply filters → **Export CSV** | CSV |
| Call tracking analytics | API only: `GET /v1/call-tracking-analytics/export`. The app has no button for it | CSV |

Exports use the same filters as the list on screen. Call records older than 6 months are not in Call Logs; see [Call Logs → Retention and archive](/modules/call-logs#retention-and-archive).

## Call statistics

**Call Logs → Statistics** shows, for the current filters:

| Metric | Meaning |
|--------|---------|
| Total calls | Number of call records |
| Total duration | Sum of call durations, in seconds |
| Total billable seconds | Sum of answered (billed) seconds |
| Average duration | Average over calls with a duration above zero |
| Total cost | Sum of the sell cost reported by Cloudonix |
| By disposition | Count per final disposition, for example CONNECTED, NO_ANSWER, BUSY, FAILED |

Queue statistics (waiting and handling times, answered, abandoned and overflow counts) are on each queue's **Statistics** tab. See [Call Queues](/modules/call-queues#reporting).

## Data retention

| Data | Kept |
|------|------|
| Call records (Call Logs) | 6 months in the main database, then 6 more months in an archive reachable by API key, then 7 years in compressed files for the platform owner |
| Live-call events | 30 days |
| Queue calls, call-tracking sessions, auto-dialer call sessions | 6 months |
| Call notification and blocked-call logs | 90 days |

Every period can be changed by environment variables. See the [Configuration Reference](/data-models/configuration/index#data-retention).

## Related API endpoints

| Method | Endpoint | Purpose |
|--------|----------|---------|
| GET | `/v1/call-detail-records` | Call records |
| GET | `/v1/call-detail-records/export` | CSV export |
| GET | `/v1/call-detail-records/statistics` | Totals and counts by disposition |
| GET | `/v1/session-updates/active` | Active calls |
| GET | `/v1/session-updates/active/stats` | Active-call counts and durations |
| GET | `/v1/queue-calls` | Queue call rows |
| GET | `/v1/queue-calls/export` | Queue call CSV export |
| GET | `/v1/dashboard/supervisor` | Supervisor dashboard data |

Scoped API keys can be limited to just these resources (for example `call-detail-records` and `dashboard` read-only). See [API Keys](/modules/api-keys).

See the [OPBX REST API reference](https://developers.cloudonix.com/opbxRestOpenAPI) for full schemas.
