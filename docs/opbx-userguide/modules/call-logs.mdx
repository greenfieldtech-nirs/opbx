# Call Logs

Call Logs shows the call detail records (CDRs) that Cloudonix sends to OPBX when a call ends. Each row is one call with its parties, disposition, durations and AMD result. You can search, open a call for details, play its recording, and export the results.

## Purpose

Use this module to:

- find a call by number, date, disposition or direction;
- open one call to see its full record and AMD result;
- play or download the call's recording, if one was made;
- export the results to CSV;
- see totals and averages for a filtered set.

Call logs are read-only. They are created by the Cloudonix call-end webhook and cannot be edited or deleted in the interface.

## Prerequisites

- Calls are flowing through Cloudonix to your OPBX instance. If the Call Logs page is empty after a test call, check the webhook settings on [Settings](/administration) and [Cloudonix Setup](/installation/cloudonix-setup).
- Only recorded calls have a recording to play. Recordings of IVR prompts and announcements are a different thing; see [Recordings](/modules/recordings).

## Who can see what

| Action | Owner | PBX Admin | PBX User | Reporter | Supervisor |
|--------|:-----:|:---------:|:--------:|:--------:|:----------:|
| Open Call Logs (sidebar) | Yes | Yes | Yes | Yes | Yes |
| See the call records | All in the organization | All in the organization | All in the organization; the page starts filtered to their own extension | All in the organization | Only calls to or from their assigned users and ring groups |
| Export CSV (button) | Yes | Yes | No | No | No |
| Play or download a recording | Yes | Yes | Yes | Yes | Only calls in their scope (single-call view) |

:::note
The PBX User's own-extension filter is only a default on the page; they can clear it. A supervisor's list is limited because the page asks for the supervisor view; the plain API list (`GET /v1/call-detail-records` without `supervisor=true`) is not limited. A single call and the CSV export are always limited to the supervisor's scope.
:::

:::caution Recording playback for PBX Users
The decision for recordings is that PBX Users may not list or play recordings from the Recordings page. **Call Logs do not apply that rule today**: any PBX User can play the recording of any call in the organization from this page. Treat this as a known gap until it is fixed.
:::

## Table columns

| Column | Meaning |
|--------|---------|
| From | Calling number |
| To | Called number |
| Session time | When the call started |
| Disposition | How the call ended, for example ANSWER, BUSY or FAILED |
| Direction | Inbound or outbound |
| User | The OPBX user who owns the extension involved, when there is one |
| Duration | Total call length in seconds |
| Billable (billsec) | Billable seconds |
| AMD | Answering machine detection result (see below) |

Click a column header to sort. Sorting by the user name is available on the live tier only (see [Retention and archive](#retention-and-archive)).

## Searching and filtering

| Filter | How it matches |
|--------|----------------|
| From number | Phone-number search (see below) |
| To number | Phone-number search (see below) |
| Disposition | Exact match |
| Direction | Exact match (inbound or outbound) |
| Date range | From the start of the first day to the end of the last day, by session time |
| Session token | Exact match on the Cloudonix session token |
| User | Matches the OPBX user who owns the extension |

### Searching numbers

- A number matches from its **start**. Typing `+1415` finds numbers that begin with `+1415`.
- The leading `+` is optional: `+1415` and `1415` both match numbers stored with or without the plus sign.
- `*` and `%` are wildcards for any characters. `*555` matches numbers that contain `555` anywhere. `+1415*` is the same as `+1415`.
- `_` is a literal character, not a wildcard.

A search with a leading wildcard works, but is slower on large data sets. Use a prefix when you can.

The same number search applies to the list, the CSV export and the statistics.

## Call details

Open a row to see:

- all the call fields, including the Cloudonix session token and call ID;
- the **AMD** result: the result label, confidence percentage, detection time in milliseconds, timestamp and reason;
- the recording player when the recording is available.

### AMD results

| Result | Meaning |
|--------|---------|
| `Enabled::human` | A person answered |
| `Enabled::voicemail` | A voicemail greeting and beep were detected |
| `Enabled::unknown` | Detection timed out or was not conclusive |
| `Disabled` | AMD was not used on this call |

## Recordings

If a call was recorded, its row has a recording and the detail dialog shows a player. The recording is streamed; it is not fully loaded into memory on the server. Downloads are limited to 200 MB per file.

A recording is removed when its retention period ends. After that the row stays, with the recording marked as not available.

## Exporting

1. Apply the filters you need.
2. Click **Export** (shown to the Owner and PBX Admins only).
3. The CSV is produced in chunks of 1000 records, so large exports do not run out of memory.

The export uses the same filters as the list, including the number-search rules.

## Statistics

Click **Statistics** to see totals, averages and a breakdown by disposition for the current filters.

## Retention and archive

Call records are kept in three tiers, by the call's session time (UTC):

| Tier | Age | Where it is | Who can reach it |
|------|-----|-------------|------------------|
| Hot | Up to 6 months | The main database | Everyone in the organization, through this page and the API |
| Warm | 6 to 12 months | A separate archive table in the database | API keys sent with `archive=1` (list, detail, export, statistics), and the platform owner's CDR archive endpoint. **Not** shown in this page |
| Cold | More than 12 months | Compressed CSV files in object storage, one per organization per hour | Platform owner only, through object storage. Kept for 7 years, then deleted |

Recordings have their own retention. They are not moved between tiers. They are deleted after `RECORDING_RETENTION_MONTHS`, which can never be longer than the cold-tier period (7 years by default). A CDR whose recording has been deleted stays, with its recording status set to none.

Retention is set by environment variables. See the [Configuration Reference](/data-models/configuration/index#data-retention).

:::note
The move from hot to warm and from warm to cold runs once a day, at 04:00 UTC. Records do not disappear at the exact moment they cross a boundary.
:::

## Related API endpoints

| Method | Endpoint | Purpose |
|--------|----------|---------|
| GET | `/v1/call-detail-records` | List (add `archive=1` for API keys to read the warm tier) |
| GET | `/v1/call-detail-records/{call_detail_record}` | One record |
| GET | `/v1/call-detail-records/{call_detail_record}/recording` | Stream the recording |
| GET | `/v1/call-detail-records/export` | CSV export |
| GET | `/v1/call-detail-records/statistics` | Totals and averages |
| GET | `/v1/platform/cdr-archive` | Warm-tier records for all organizations (platform owners) |

See the [OPBX REST API reference](https://developers.cloudonix.com/opbxRestOpenAPI) for full schemas.

## Common problems

| Symptom | Likely cause |
|---------|--------------|
| A call is missing | The call-end webhook did not reach OPBX. Check [Settings](/administration) and the Cloudonix webhook configuration |
| Recording button is missing | The call was not recorded, or the recording was deleted by retention |
| A search finds nothing for a number | Number search matches the start of the number. Add a wildcard (`*`) in front of the part you want |
| A call older than 6 months is missing from this page | It moved to the warm tier. Use the API with an API key and `archive=1` |
