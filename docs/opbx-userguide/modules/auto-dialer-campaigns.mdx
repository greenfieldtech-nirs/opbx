# Auto Dialer Campaigns

An auto-dialer campaign dials every number on its [distribution lists](/opbx/modules/distribution-lists) (a campaign can hold several) inside a weekly schedule, at a controlled rate, and connects answered calls to an AI assistant or AI load balancer. This page is the reference and the list of workflows. The step-by-step screen walk-through is in the **Auto Dialer** application guide, starting at [Auto Dialer Overview](/opbx/applications/auto-dialer).

## Purpose

Use this module to:

- create and edit outbound campaigns;
- choose the routing destination and the caller-ID pool;
- set the schedule, rate limits, attempts and voicemail detection;
- start, pause, resume, archive or delete campaigns;
- follow progress on the [Real-Time Monitor](/opbx/applications/auto-dialer/real-time-monitor).

## Prerequisites

- **Owner** or **PBX Admin** role to change anything; **Reporter** may view.
- An [AI assistant](/opbx/modules/ai-assistants) or [AI load balancer](/opbx/modules/ai-load-balancers), unless you route to Hangup for testing.
- At least one **active** [phone number](/opbx/modules/phone-numbers) for the caller ID.
- The [dialer worker](/opbx/workers/dialer-worker) running (single replica), and the [AMD worker](/opbx/workers/amd-worker) for voicemail detection.

## Workflows

The Auto Dialer screens are documented step by step in the **Auto Dialer** application guide. Each workflow below says who can do it and links to the steps.

![Campaign Manager with Fall Webinar Follow-up (Paused, AI Assistant routing)](../img/screens/auto-dialer-campaign-list.jpg)

### Find a campaign

**Who can do this:** Owner, PBX Admin, Reporter.

Open **Auto Dialer → Campaign Manager**, type in **Search campaigns...** or pick a status (the default is **All (except Archived)**), and click **Clear Filters** to reset. See [The Campaign Manager page](/opbx/applications/auto-dialer/campaigns#the-campaign-manager-page).

A Reporter sees the list with a **Read-Only** badge and no action buttons, and clicking a row does not open the campaign.

### Create a campaign

**Who can do this:** Owner, PBX Admin.

Click **Create Campaign**, fill in the **Basic Info**, **Schedule**, **Answering Machine Detection** and **Advanced** tabs, and save. The campaign is stored as **Draft**. See [Create a campaign](/opbx/applications/auto-dialer/campaigns#create-a-campaign), and for the tabs [Campaign Scheduling](/opbx/applications/auto-dialer/scheduling#set-the-schedule), [Answering Machine Detection](/opbx/applications/auto-dialer/answering-machine-detection#turn-detection-on), [Rate Limiting](/opbx/applications/auto-dialer/rate-limiting) and [Campaign Routing](/opbx/applications/auto-dialer/routing-destinations#set-the-destination).

### Assign a distribution list to a campaign

**Who can do this:** Owner, PBX Admin.

See [Assign a list to a campaign](/opbx/applications/auto-dialer/distribution-lists#assign-a-list-to-a-campaign). A campaign needs a Ready list before it can start, and can hold several lists; their pending numbers are dialed together, the numbers added earliest first. A list can be taken back (from Distribution Lists or the campaign's detail page) only until the campaign has started processing its entries; after that it stays with the campaign. See [Take a list back from a campaign](/opbx/applications/auto-dialer/distribution-lists#take-a-list-back-from-a-campaign).

### Start, pause or resume a campaign

**Who can do this:** Owner, PBX Admin.

Click the status badge on the row (Draft starts, Running pauses, Paused resumes; the list confirms "Campaign status updated"), or use **Start**, **Pause** or **Resume** on the campaign's detail page, or **Pause** and **Resume** on the [Real-Time Monitor](/opbx/applications/auto-dialer/real-time-monitor#pause-and-resume-from-the-monitor). See [Start, pause, resume](/opbx/applications/auto-dialer/campaigns#start-pause-resume).

### Edit a campaign

**Who can do this:** Owner, PBX Admin. The campaign must not be Running.

See [Edit a campaign](/opbx/applications/auto-dialer/campaigns#edit-a-campaign).

### View a campaign's progress

**Who can do this:** Owner, PBX Admin (from the list). A Reporter can open the detail page only by its address; the list rows are not clickable for them.

Click the campaign's row or name. See [The campaign detail page](/opbx/applications/auto-dialer/campaigns#the-campaign-detail-page) and the [Real-Time Monitor](/opbx/applications/auto-dialer/real-time-monitor#drill-down).

### Archive a campaign

**Who can do this:** Owner. The **Archive** buttons are hidden from other roles.

See [Archive a campaign](/opbx/applications/auto-dialer/campaigns#archive-a-campaign). The list confirms "Campaign archived successfully".

### Delete a campaign

**Who can do this:** Owner, and only for a Draft campaign. The delete button is hidden from other roles.

See [Delete a campaign](/opbx/applications/auto-dialer/campaigns#delete-a-campaign). The list confirms "Campaign deleted successfully".

### API-only tasks

Resetting the concurrent-call counter (`reset-cac`) and restarting the caller-ID round robin (`reset-caller-id-cycle`) have no button. Use the API endpoints below.

## Fields at a glance

| Field | Limits and default |
|-------|--------------------|
| Name | Required, up to 255 characters |
| Description | Up to 1000 characters (API only; the form does not show it) |
| Routing destination | AI Assistant, AI Load Balancer or Hangup. A destination ID is required except for Hangup |
| Caller ID | Required, E.164. The form uses the first number of the pool |
| Caller-ID pool | 1 to 100 active numbers of your organization; weight 1 to 100 per number (API only, default 1) |
| Caller-ID strategy | Round Robin (default), Random, Least Recently Used |
| Timezone | Required, IANA name |
| Start and end date | Required. Start today or later on create; end on or after start |
| Weekly schedule | Per weekday: enabled, and time ranges `HH:MM` to `HH:MM` (end may be `24:00`) |
| Dial timeout | 1 to 300 seconds. Form default: 60 |
| Connect when | Call Connected or Immediately. Sent to Cloudonix as `execute` |
| Time limit | 30 to 14400 seconds. Default: 600, also when the field is left empty or the API receives null |
| Concurrent active calls (CAC) | 1 to 50. Form default: 1 |
| Calls per second (CPS) | 1 to 30. Default: 1 |
| Max dial attempts | 1 to 5. Form default: 1 |
| Record calls | Off by default |
| Voicemail, human and unknown actions | `HANGUP` or `CONTINUE`, or empty (treated as Continue). Empty on all three means no detection |
| Retry on voicemail | Off by default |
| Retry on busy / no-answer | `retry_on_busy_no_answer`, off by default. Cancelled and failed calls are never retried |
| First retry delay | `retry_delay_minutes`, 1 to 1440, default 15; each further retry waits twice as long, capped at 24 hours |
| Auto-start | Off by default |

## Statuses

| Status | Shown as | Meaning |
|--------|----------|---------|
| `draft` | Draft | New. Editable and deletable |
| `active` | Running | Dials whenever the schedule allows. Not editable |
| `paused` | Paused | No new calls. Editable |
| `completed` | Completed | Every number finished. Set automatically only for auto-started campaigns |
| `archived` | Archived | Kept for history |

Assigning a Ready list does not start a campaign: it stays **Draft** until someone starts it, or until auto-start does.

## What a campaign blocks

- A **phone number** in a campaign's caller-ID pool cannot be deleted ("caller ID pool" in the in-use dialog).
- An **AI assistant** or **AI load balancer** that a campaign routes to cannot be deleted ("routing" in the in-use dialog), whatever the campaign's status.

Remove the reference from the campaign first. See [Phone Numbers](/opbx/modules/phone-numbers#delete) and [Campaign Routing](/opbx/applications/auto-dialer/routing-destinations#deleting-a-destination-that-a-campaign-uses).

## Key data fields

### `auto_dialer_campaigns`

| Column | Notes |
|--------|-------|
| `id`, `organization_id` | Key and tenant scope |
| `name`, `description` | |
| `status` | `draft`, `active`, `paused`, `completed`, `archived` |
| `auto_start` | Boolean |
| `routing_destination_type`, `routing_destination_id` | `ai_assistant`, `ai_load_balancer` or `hangup`, and the target id |
| `caller_id`, `caller_id_strategy`, `caller_id_pool_enabled` | Main caller ID and pool settings |
| `dial_timeout`, `time_limit`, `destination_connect`, `record_calls` | Call settings |
| `max_dial_attempts`, `concurrent_active_calls`, `calls_per_second` | Limits |
| `timezone`, `start_date`, `end_date`, `schedule` | The schedule. `schedule` is the weekly JSON that the dialer reads |
| `days_active`, `start_time`, `end_time` | Older single-window fields derived from `schedule`; used by auto-start |
| `action_voicemail`, `action_human`, `action_unknown`, `retry_on_voicemail` | Voicemail detection |
| `total_destinations`, `completed_calls`, `failed_calls`, `pending_calls`, `voicemail_calls` | Counters |
| `started_at`, `completed_at` | Timestamps |

### `auto_dialer_campaign_caller_ids`

The caller-ID pool: `campaign_id`, `did_number_id`, `weight`.

### `auto_dialer_call_sessions`

One row per call attempt: campaign, destination, session token, status, disposition, duration, AMD result and confidence, and the start, answer and end times.

## Related API endpoints

| Method | Endpoint | Purpose |
|--------|----------|---------|
| GET | `/v1/auto-dialer-campaigns` | List (filters: `status`, `exclude_status`, `search`) |
| POST | `/v1/auto-dialer-campaigns` | Create (status Draft) |
| GET | `/v1/auto-dialer-campaigns/{campaign}` | One campaign, with its caller-ID pool |
| PUT | `/v1/auto-dialer-campaigns/{campaign}` | Update (refused while Active) |
| DELETE | `/v1/auto-dialer-campaigns/{campaign}` | Delete (Owner, Draft only) |
| PATCH | `/v1/auto-dialer-campaigns/{campaign}/start` | Start |
| PATCH | `/v1/auto-dialer-campaigns/{campaign}/pause` | Pause |
| PATCH | `/v1/auto-dialer-campaigns/{campaign}/resume` | Resume |
| PATCH | `/v1/auto-dialer-campaigns/{campaign}/archive` | Archive (Owner) |
| POST | `/v1/auto-dialer-campaigns/{campaign}/reset-cac` | Reset the concurrent-call counter |
| GET | `/v1/auto-dialer-campaigns/{campaign}/list` | Every list assigned to the campaign, with `can_unassign` and `unassign_refusal` |
| POST | `/v1/auto-dialer-campaigns/{campaign}/list` | Upload a CSV as another list of the campaign |
| DELETE | `/v1/auto-dialer-campaigns/{campaign}/list/{list}` | Unassign one list (403 while the campaign is active, 422 once its entries have started processing) |
| GET | `/v1/auto-dialer-campaigns/{campaign}/destinations` | Numbers of the campaign's lists |
| GET | `/v1/auto-dialer-campaigns/{campaign}/concurrency` | Live CAC use |
| GET | `/v1/auto-dialer-campaigns/monitor/summary` | Monitor overview |
| GET | `/v1/auto-dialer-campaigns/{campaign}/monitor/detail` | Monitor drill-down |
| GET | `/v1/auto-dialer-campaigns/available-caller-ids` | Active numbers that can join a pool. Optional `exclude_campaign_id` (integer) leaves out the numbers already in that campaign's pool |
| GET | `/v1/auto-dialer-campaigns/{campaign}/caller-id-stats` | Per-number usage |
| POST | `/v1/auto-dialer-campaigns/{campaign}/reset-caller-id-cycle` | Restart round robin (Paused only) |

**Scoped API keys** use the `auto-dialer-campaigns` resource. The **MCP server** offers tools such as `list_campaigns`, `get_campaign`, `create_campaign`, `update_campaign` and `get_campaigns_monitor_summary`. See [API Keys](/opbx/modules/api-keys) and [MCP Server](/opbx/modules/mcp-server).

See the [OPBX REST API reference](https://developers.cloudonix.com/opbxRestOpenAPI) for full schemas.
