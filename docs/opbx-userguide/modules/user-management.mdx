# User Management

The Users page controls who can sign in to your organization and what each person can do. Each user belongs to exactly one organization and has exactly one role.

## Purpose

Use this module to:

- add people to the organization;
- set each person's role;
- activate or deactivate accounts;
- set passwords;
- remove a person and see what that changes in routing.

## Prerequisites

- You are the **Owner** or a **PBX Admin**. Other roles cannot open the Users page.
- For a PBX User to take queue calls or be called, give them an **extension**. See [Extensions](/modules/extensions).

## Roles

| Role | What it is for |
|------|----------------|
| **Owner** | Runs the organization. Full access, including role changes and Cloudonix settings |
| **PBX Admin** | Day-to-day administration of routing, numbers and users |
| **PBX User** | An employee with an extension. Manages their own profile and queue login |
| **Reporter** | Read-only access to reports, call logs and most configuration |
| **Supervisor** | Watches and coaches only the users and groups assigned to them. See [Supervisors](/modules/supervisors) |

:::info The Owner role
The **Owner** role cannot be assigned through the API or the Users page: the server refuses it with "Owner role cannot be assigned. Each organization has a single owner." An organization's Owner is set up when the organization is created. Only an Owner can change another user's role, and an Owner cannot change their own role.
:::

## Permissions

| Action | Owner | PBX Admin | PBX User | Reporter | Supervisor |
|--------|:-----:|:---------:|:--------:|:--------:|:----------:|
| See the user list | Yes | Yes | No | No | Yes (self and assigned users) |
| Open a user | Yes | Yes | Self only | Self only | Self and assigned users |
| Create a user | Yes | Yes, but not an Owner or PBX Admin account | No | No | No |
| Edit a user | Yes | Yes, with the limits below | Self only | No | No |
| Change a role | Yes, not their own | No | No | No | No |
| Activate or deactivate | Yes, not themselves, not the Owner | Yes, same limits as Owner | No | No | No |
| Set a password | Yes, not their own (here) | PBX User and Reporter only | No | No | No |
| Delete | Yes, not themselves | Yes, not themselves (see the note below) | No | No | No |

PBX Admin limits when editing:

- an Admin cannot change the role of a user who is an Owner or a PBX Admin;
- an Admin cannot give the PBX Admin role to anyone;
- an Admin cannot set the Owner role.

:::caution Open question: PBX Admin can delete an Owner
The permission to delete a user is the same for Owners and PBX Admins, and only the **last** Owner is protected. A PBX Admin can therefore delete another Owner or PBX Admin. The guide describes the code as it stands; confirm the intended rule before you rely on it.
:::

## Create a user

1. Open **Users** in the sidebar.
2. Click **Add User**.
3. Fill in the fields below and choose a role.
4. Save.

| Field | Required | Limit | Notes |
|-------|----------|-------|-------|
| Name | Yes | 2 to 255 characters | |
| Email | Yes | Valid email, up to 255 characters, unique within the organization | Used to sign in |
| Password | Yes | At least 8 characters, with letters (upper and lower case) and numbers | Set by the admin when you create the account |
| Role | Yes | Owner (refused), PBX Admin, PBX User, Reporter, Supervisor | An Admin cannot create an Owner or a PBX Admin |
| Status | No | Active or Inactive. Default: Active | |
| Phone | No | Up to 50 characters | |
| Street address, city, state or province, postal code, country | No | 255, 100, 100, 20 and 100 characters | |

### Invite instead of setting a password

**Invite user** sends an invitation by email. It is available only when Auth0 sign-in is enabled for the deployment. If it is not, the button is disabled with a tooltip (the server would answer that Auth0 is not enabled). Invitations to an email address already in use are refused.

## Edit a user

1. Click the user, then **Edit**.
2. Change the fields you need and save.

Two changes need care:

- **Role**: only an Owner can change it, and not their own.
- **Status**: change it on the user's row or in the editor. Deactivating a user keeps their history. Nobody can deactivate themselves, and nobody can deactivate the Owner.

## Set a password

Open the user and choose **Set password**, then enter and confirm the new password. The same password rules as on create apply. You cannot change your own password here; use your profile instead (see [Organization Settings](/administration)).

## Delete a user

Deleting a user does not delete their extension. Before the delete is sent, a **Delete User** dialog lists exactly what will change, computed by the same code that performs the delete:

| What happens | Detail |
|--------------|--------|
| The user's extensions are kept | They are unassigned and can be given to a new user |
| Ring-group memberships | The user is removed. A ring group left with no members is allowed |
| Call-queue memberships | The user is removed. A queue left with no agents is allowed and is flagged in the dialog |
| Routes that pointed at those extensions | Changed to **Destination unavailable**. Callers hear "Destination doesn't exist" and the call ends |

The routes changed can be on IVR options and their failover, ring-group and queue fallbacks, AI load balancer fallbacks, phone numbers, business-hours actions and call-tracking campaigns.

Confirm only after reading the list. The Owner cannot be deleted while they are the last Owner, and nobody can delete their own account.

![Delete User dialog listing the kept extension, a removed ring group membership and the IVR and DID routes that will become Destination unavailable](../img/screens/platform-user-delete-preview.jpg)

After the delete, the routes that were changed show **Unprovisioned** in their own lists. Fix them by choosing a new destination on the edit screen. See [IVR Menus](/modules/ivr-menus) and [Phone Numbers](/modules/phone-numbers).

## Deactivate a user

1. Click **Deactivate** on the user's row, or set Status to Inactive in the editor.
2. Confirm.

Use this instead of deleting when someone leaves temporarily, or when you want to keep the account and its history.

## Key data fields

### `users`

| Column | Notes |
|--------|-------|
| `id` | Primary key |
| `organization_id` | Tenant scope |
| `name` | Display name |
| `email` | Unique within the organization |
| `password` | Stored hashed |
| `role` | `owner`, `pbx_admin`, `pbx_user`, `reporter` or `supervisor` |
| `status` | `active` or `inactive` |
| `is_platform_manager` | Platform-level flag. Set by platform managers, not from this page |

## Related API endpoints

| Method | Endpoint | Purpose |
|--------|----------|---------|
| GET | `/v1/users` | List users |
| POST | `/v1/users` | Create a user |
| GET | `/v1/users/{user}` | One user |
| PUT | `/v1/users/{user}` | Update a user (role and status rules above apply) |
| GET | `/v1/users/{user}/delete-impact` | The changes a delete would make, without deleting |
| DELETE | `/v1/users/{user}` | Delete (409 for the last Owner) |
| PATCH | `/v1/users/{user}/password` | Set a password |
| POST | `/v1/users/invite` | Invite by email (needs Auth0) |

See the [OPBX REST API reference](https://developers.cloudonix.com/opbxRestOpenAPI) for full schemas.
