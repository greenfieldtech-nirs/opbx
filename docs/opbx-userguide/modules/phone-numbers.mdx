# Phone Numbers (DIDs)

A phone number (DID, direct inward dial) is a number that outside callers dial to reach your organization. Each DID has one routing destination: an extension, ring group, queue, IVR menu, business-hours schedule, conference room, AI assistant or AI load balancer.

## Purpose

Use this module to:

- add the numbers your organization owns;
- route each number to a destination;
- turn a number on or off;
- use a number as the caller ID for outbound calls (see below).

## Prerequisites

- The number is provisioned in Cloudonix and points at your OPBX instance. See [Cloudonix Setup](/installation/cloudonix-setup).
- The destination exists and is **active**. Creating a DID is refused if its destination is inactive, missing, or belongs to another organization.

## Permissions

| Action | Owner | PBX Admin | PBX User | Reporter |
|--------|:-----:|:---------:|:--------:|:--------:|
| See Phone Numbers in the sidebar | Yes | Yes | No | Yes |
| Create | Yes | Yes | No | No |
| Edit routing or status | Yes | Yes | No | No |
| Delete | Yes | Yes | No | No |

## Number format

The number must be in **E.164** format: a plus sign, a first digit from 1 to 9, then 1 to 14 more digits. For example `+14155551234`. Maximum 20 characters.

A **non-E.164** option accepts digits, `+` and `#` only. Use it for internal or special-use numbers that are not valid E.164.

The number must be **unique across all organizations**. A number that another organization already has is refused with "This phone number is already registered."

:::warning Numbers cannot be changed
The number is fixed after creation. To change it, delete the DID and create a new one. The delete is refused while the number is used elsewhere (see [Delete](#delete)).
:::

## Fields

| Field | Required | Limit | Meaning |
|-------|----------|-------|---------|
| Phone number | Yes | E.164 (or digits, `+`, `#` in non-E.164 mode), max 20 characters | The number callers dial |
| Friendly name | No | Up to 255 characters | A label for your lists, for example "Main line" |
| Routing type | Yes | See the table below | What kind of destination the call goes to |
| Destination | Yes | Pick one existing, active item | The item itself |
| Status | Yes | Active or Inactive. Default: Active | Whether the number is used for routing |

### Routing types

| Routing type | Routes to | Typical use |
|--------------|-----------|-------------|
| Extension | One extension | Direct line |
| Ring group | A ring group | Department coverage |
| Call queue | A call queue | Support or sales line that needs waiting and statistics |
| IVR menu | A menu | Main company number with "press 1 for…" |
| Business hours | A business-hours schedule | Open and closed handling |
| Conference room | A conference room | Dedicated conference line |
| AI assistant | An AI assistant | Automated answering |
| AI load balancer | An AI load balancer | High-volume AI answering |

Each destination must be **active**. A destination that is inactive, deleted, or belongs to another organization is refused.

## Create a phone number

1. Open **Phone Numbers** in the sidebar.
2. Click **Add Phone Number**.
3. Enter the number in E.164 format, for example `+14155551234`.
4. Enter a friendly name if you want one.
5. Choose the routing type, then the destination.
6. Save.

![Phone Numbers list with the demo numbers, one Unprovisioned, and the Unprovisioned filter button](../img/screens/phone-numbers-list.jpg)

![Add Phone Number dialog with a valid E.164 number, routing type Call Queue and the queue picker open](../img/screens/phone-numbers-create-dialog.jpg)

A new number must be fully routed. The **Destination unavailable** choice is not offered when you create a number.

## Change routing

1. Click the number in the list.
2. Change the routing type or destination, or the status.
3. Save.

On the edit screen only, the destination can be set to **Disconnect**. That stores "Destination unavailable" and the number shows the **Unprovisioned** badge. Callers hear "Destination doesn't exist" and the call ends. Use it when a number is provisioned but not yet in service.

![Edit dialog for the unprovisioned number +12025550105, with the Unprovisioned badge in the title and Destination unavailable selected](../img/screens/phone-numbers-unprovisioned.jpg)

## Status

| Status | Meaning |
|--------|---------|
| Active | Calls to the number are routed to its destination |
| Inactive | The number is not used for routing |

Set a number to Inactive while it is being ported, to block calls temporarily, or while it is reserved.

## Delete

Deleting asks for confirmation. The delete is refused while the number is assigned as configuration somewhere else:

- the default caller ID of an extension;
- a call-tracking number;
- the caller ID of an outbound whitelist rule;
- a caller-ID pool of an auto-dialer campaign;
- a scope of an inbound blacklist.

The refusal opens a dialog that lists each place. Remove those assignments, then delete the number. Call history (call logs, CDRs, call-tracking sessions, blocked-call logs) never blocks a delete.

## Using a number as an outbound caller ID

Besides receiving calls, an **active** number can be shown as the caller ID on outbound calls. Assign it as the default caller ID on an [extension](/modules/extensions) or on an [outbound whitelist](/modules/outbound-whitelist) rule.

Only active numbers owned by your organization can be used this way. When the chosen number is not usable, outbound calls fall through to the next caller ID in the precedence order. See the [Outbound Calling Overview](/installation/outbound-calling-overview).

:::note
The organization-wide default caller ID (`GET` and `PUT /v1/phone-numbers/default-caller-id`) is deprecated. Call routing no longer reads it. Use the per-extension and per-whitelist default instead.
:::

## Key data fields

### `did_numbers`

| Column | Notes |
|--------|-------|
| `id` | Primary key |
| `organization_id` | Tenant scope |
| `phone_number` | String up to 20 characters. Unique across all organizations. Cannot be changed |
| `friendly_name` | Optional label, up to 255 characters |
| `routing_type` | `extension`, `ring_group`, `call_queue`, `ivr_menu`, `business_hours`, `conference_room`, `ai_assistant`, `ai_load_balancer` or `unavailable` |
| `routing_config` | JSON with the target id, for example `{"extension_id": 12}` |
| `status` | `active` or `inactive` |

## Related API endpoints

| Method | Endpoint | Purpose |
|--------|----------|---------|
| GET | `/v1/phone-numbers` | List |
| POST | `/v1/phone-numbers` | Create. Rejects "Destination unavailable" |
| GET | `/v1/phone-numbers/{phoneNumber}` | One number |
| PUT | `/v1/phone-numbers/{phoneNumber}` | Update routing and status. The number itself is refused if sent |
| DELETE | `/v1/phone-numbers/{phoneNumber}` | Delete. Returns 409 with the list of uses when in use |

See the [OPBX REST API reference](https://developers.cloudonix.com/opbxRestOpenAPI) for full schemas.

## Best practices

- Label each number with its purpose (Sales, Support, Main).
- Keep the same routing pattern for similar numbers.
- Test each number after you change its routing.
