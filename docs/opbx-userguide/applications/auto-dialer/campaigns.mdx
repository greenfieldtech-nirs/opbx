# Managing Campaigns

A campaign holds everything about one outbound calling run: where answered calls go, which caller IDs to show, when to dial, how fast, how often to retry and what to do when a voicemail answers. The numbers themselves live in a [distribution list](/opbx/applications/auto-dialer/distribution-lists) that you assign to the campaign.

## Purpose

Use **Campaign Manager** to:

- create a campaign and edit it while it is Draft or Paused;
- start, pause, resume and archive it;
- delete a Draft campaign (Owner only; archiving is Owner only too);
- see its progress, settings, assigned lists and caller-ID usage.

## Prerequisites

- You are the **Owner** or a **PBX Admin**. Some actions are **Owner only** (see [Permissions](#permissions)).
- An [AI assistant](/opbx/modules/ai-assistants) or [AI load balancer](/opbx/modules/ai-load-balancers) to receive answered calls, unless you only want to test with **Hangup**.
- At least one **active** [phone number](/opbx/modules/phone-numbers) of your organization to use as the caller ID.

## The Campaign Manager page

Open **Auto Dialer → Campaign Manager**. Each row shows the campaign name, status badge, caller ID (or the number of caller IDs in the pool and the strategy), assigned lists, the CAC limit, the routing destination and the creation date.

- **Search** filters by name.
- **Status filter**: All (except Archived) is the default. You can also pick All Statuses, Draft, Running, Paused, Completed or Archived.
- **The status badge is a button** for managers: on a Draft it starts the campaign, on Running it pauses, on Paused it resumes. Completed and Archived badges do nothing.
- **Row actions** depend on the status:

| Status | Actions on the row |
|--------|--------------------|
| Draft | **Edit**, **Delete** (Delete is for the Owner only) |
| Running | **Edit** (disabled, with the hint "Pause the campaign to edit") |
| Paused | **Edit** |
| Completed | **Archive** (Owner only) |
| Archived | None |

## Create a campaign

1. Click **Create Campaign**.
2. Fill in the four tabs described below: **Basic Info**, **Schedule**, **Answering Machine Detection** and **Advanced**.
3. Click **Create Campaign** at the bottom.

On save the campaign is stored in **Draft** status and you land on its detail page. Nothing is dialed yet. To dial, assign a Ready distribution list (the campaign stays **Draft**), then press **Start**, or turn on **Auto-start**.

![Create Campaign form, Basic Info tab, with routing destination AI Assistant Aria - Front Desk Receptionist and one caller ID selected in the pool](../../img/screens/auto-dialer-campaign-create-basic.jpg)

### Basic Info tab

| Field | Limits and default | Meaning |
|-------|--------------------|---------|
| Campaign Name | Required, up to 255 characters | Shown in lists and the monitor |
| Routing Destination | AI Assistant, AI Load Balancer or Hangup. Required | Where answered calls go. See [Campaign Routing](/opbx/applications/auto-dialer/routing-destinations) |
| Select Destination | Required unless the type is Hangup | The assistant or load balancer |
| Caller ID Strategy | Round Robin (default), Random, Least Recently Used | How the next caller ID is chosen from the pool |
| Caller ID Pool | 1 to 100 numbers. Only **active** numbers of your organization are offered | The numbers callees see. The first number is also stored as the campaign's main caller ID |

The pool can only be changed while the campaign is **Draft** or **Paused**. On an active campaign the pool section shows **Pool Locked**.

### Caller ID strategies

| Strategy | How the next caller ID is chosen |
|----------|----------------------------------|
| Round Robin | Each number in turn. Numbers with a higher weight are used more often (weights can be set through the API only; the default is 1) |
| Random | A random number from the pool |
| Least Recently Used | The number that was used longest ago |

When a number is **retried**, the dialer prefers a caller ID that has not yet been tried for that number.

:::note Caller-ID numbers are protected
A phone number in a campaign's caller-ID pool cannot be deleted. The delete is refused and the dialog lists the campaign as a "caller ID pool" use. Remove the number from the pool first. See [Phone Numbers](/opbx/modules/phone-numbers#delete).
:::

### Schedule tab

| Field | Limits and default | Meaning |
|-------|--------------------|---------|
| Timezone | Required, any IANA timezone. Default: UTC | The clock the schedule and dates are read in |
| Start Date | Required. Today or later when you create | First day the campaign may dial |
| End Date | Required. On or after the start date | Last day the campaign may dial |
| Active Hours | A weekly grid. New campaigns start with Monday to Friday, 09:00 to 17:00 | The hours each weekday when dialing is allowed. Click time slots to toggle them |

See [Campaign Scheduling](/opbx/applications/auto-dialer/scheduling) for how the window is evaluated.

### Answering Machine Detection tab

| Field | Limits and default | Meaning |
|-------|--------------------|---------|
| Enable Detection | Off by default | Streams the call audio to the AMD worker, which listens for a voicemail beep |
| If Voicemail Detected | Hang up (default when enabled) or Continue to destination | Applied when a beep is heard |
| If Human Detected | Continue to destination (default when enabled) or Hang up | See the note on the AMD page: the detector does not report "human" today |
| If Detection Unclear | Hang up (default when enabled) or Continue to destination | Applied when no beep is heard within the detection window |
| Retry on Voicemail | Off by default | Schedules another attempt when a voicemail was detected |

:::warning Read the AMD page before you enable detection
With the defaults, a call where no beep is heard is **hung up** when the detection window ends, which includes calls answered by a person. Read [Answering Machine Detection](/opbx/applications/auto-dialer/answering-machine-detection) and set **If Detection Unclear** to **Continue to destination** unless you really want that.
:::

Each action offers **Hang up** or **Continue to destination**. When you turn detection off on the edit form, the saved actions are cleared.

### Advanced tab

| Field | Limits and default | Meaning |
|-------|--------------------|---------|
| Auto-start | Disabled by default | Lets the scheduler start a Draft campaign on schedule (see [Auto-start](/opbx/applications/auto-dialer/scheduling#auto-start)) |
| Time Limit (sec) | 30 to 14400. Default: 3600 | Maximum length of one call |
| Dial Timeout (sec) | 1 to 300. Default: 60 | How long the callee's phone rings before the attempt is given up |
| Connect When | Call Connected (default) or Immediately | Sent to Cloudonix as `execute`. **Call Connected** starts the call flow (routing, AMD) when the callee answers; **Immediately** starts it while the callee's phone is still ringing |
| Concurrent Active Calls (CAC) | 1 to 50. Default: 1 | Most calls in progress at once |
| Calls Per Second (CPS) | 1, 2, 3, 4, 5, 6, 10, 12, 15, 20, 25 or 30. Default: 1 | How fast new calls are started |
| Max Dial Attempts | 1 to 5. Default: 1 | Most attempts per number, including retries |
| Retry on busy / no-answer | Off by default | Redials a number whose call ended busy or unanswered, within Max Dial Attempts. Cancelled, failed and congested calls are never retried |
| First retry delay (minutes) | 1 to 1440. Default: 15. Shown when the retry switch is on | Wait before the first redial; each further retry waits twice as long, up to 24 hours |
| Record Calls | Off by default | Asks Cloudonix to record each call |

See [Rate Limiting](/opbx/applications/auto-dialer/rate-limiting) for CAC, CPS and attempts.

:::note Connect When and detection
Cloudonix turns its own machine detection off when a call is not started with **Call Connected**. If you use [Answering Machine Detection](/opbx/applications/auto-dialer/answering-machine-detection), keep **Call Connected**.
:::

## What happens when a call is placed

For each number, OPBX:

1. claims the number so it is dialed once, even if two requests race;
2. picks the caller ID from the pool;
3. chooses the outbound trunk from the first matching [outbound whitelist](/opbx/modules/outbound-whitelist) rule. When no rule matches, Cloudonix chooses the trunk;
4. asks Cloudonix to dial, with the dial timeout, time limit, recording flag and a 5-minute start deadline;
5. counts the call against the CAC limit until Cloudonix reports it ended.

If Cloudonix refuses the call, the number goes back to pending and is tried again after 1 minute, then 2 minutes; after **3 consecutive** refusals it is marked **Failed**.

## Start, pause, resume

| Action | Where | Allowed from | What happens |
|--------|-------|--------------|--------------|
| **Start** | Status badge on a Draft row, or **Start** on the detail page | Draft or Paused | Needs a list assigned (Ready or In Use). Status becomes Active (Running). The concurrent-call counter is reset |
| **Pause** | Running badge, **Pause** on the detail page, or the monitor | Active | No new calls. Calls still recorded as in progress are closed as cancelled and the concurrent-call counter is reset. OPBX does not hang up calls that are already connected |
| **Resume** | Paused badge, **Resume** on the detail page, or the monitor | Paused | Status becomes Active. The counter is reset |

On the detail page each action asks for confirmation first.

An Active campaign only dials inside its schedule. Outside the window it stays **Running** but places no calls.

A campaign becomes **Completed** by itself, within a minute, once nothing is left to dial: every number is completed, failed or invalid, or pending with no attempts left, and no call is in progress. This applies however the campaign was started. A completed campaign can be archived.

## Edit a campaign

1. Pause the campaign if it is Running. **Edit** is disabled on Running campaigns and the server refuses the change with "Cannot modify an active campaign. Please pause it first."
2. Click **Edit** on the row or on the detail page.
3. Change the fields and click **Update Campaign**.

The start date may be in the past when you edit. The caller-ID pool can be changed only while the campaign is Draft or Paused; on an Active campaign the server answers 409 "Cannot modify Caller ID pool on an active campaign".

:::note Turning detection off
Switching **Enable Detection** off in the edit form does not clear the saved actions on the server, so detection stays on after you save. To really turn it off, set every action to **Continue to destination**, or clear the actions through the API.
:::

## Archive a campaign

1. Click **Archive** on a Completed row, or **Archive** on any campaign's detail page.
2. Confirm. The dialog warns that this cannot be undone.

Archiving an Active campaign pauses it first. Archived campaigns cannot be restored from the app. Only the **Owner** can archive; a PBX Admin sees the button but the server refuses.

## Delete a campaign

1. Click **Delete** on a **Draft** row.
2. Confirm in the **Delete Campaign** dialog. It says the campaign's lists stay in the system.

Only **Draft** campaigns can be deleted, and only by the **Owner**. A PBX Admin sees the button but the server refuses. Use **Archive** for campaigns that have dialed.

## The campaign detail page

Click a campaign name. The header shows the status badge, an **Auto-start** badge when enabled, and the **Edit**, **Start**/**Pause**/**Resume** and **Archive** buttons. The page refreshes every 10 seconds.

| Card | Meaning |
|------|---------|
| Total Destinations | Numbers on the assigned lists |
| Completed | Calls completed |
| Failed | Numbers that failed after their attempts |
| Voicemail | Calls where voicemail was detected |
| Pending | Numbers not yet dialed or waiting for a retry |
| Progress | Completed and failed as a share of the total |

Below the cards: the full configuration (routing, caller ID strategy and pool, dial timeout, connect mode, attempts, CAC), the assigned distribution lists (name, version, records, invalid), the schedule (timezone, date range, active days), time limit, recording and the voicemail detection actions, or "Not configured".

## Common errors

| Message (summary) | What it means | What to do |
|-------------------|---------------|-----------|
| Caller ID must be in E.164 format | No caller ID was chosen, or the number is not E.164 | Add at least one number to the pool |
| Invalid Caller ID pool: some DIDs do not exist, do not belong to your organization, or are not active | A pool number is inactive or not yours | Activate the number or remove it |
| A destination ID is required when routing to AI Assistant or AI Load Balancer | No destination picked | Pick the assistant or load balancer |
| The start date must be a date after or equal to today | Start date in the past on create | Pick today or later |
| Cannot modify an active campaign. Please pause it first | Edit sent while Running | Pause, then edit |
| Cannot modify Caller ID pool on an active campaign | Pool change while Running | Pause first |
| Cannot start campaign without a destination list | No list assigned, or the list is archived, used or failed | Assign a Ready list |
| This action is unauthorized | A PBX Admin tried to archive or delete, or the campaign is not Draft | Ask the Owner, or archive instead of delete |
