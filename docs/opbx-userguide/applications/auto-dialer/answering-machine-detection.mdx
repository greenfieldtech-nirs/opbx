# Answering Machine Detection

Answering machine detection (AMD) tells a campaign whether a call reached a voicemail box. OPBX streams the first seconds of each answered call to its **AMD worker**, which listens for the **voicemail beep**. The campaign then hangs up or carries on, according to the actions you set.

## Purpose

Use AMD to avoid spending an AI conversation on voicemail boxes, to count how many calls reached voicemail, and (optionally) to try those numbers again later.

## Prerequisites

- The AMD worker is running and reachable by Cloudonix through your public address (path `/ws/amd/`). See [AMD Worker](/workers/amd-worker).
- The Cloudonix integration has its webhook base URL set; the stream address is built from it. Without it, calls are placed **without** detection.
- A campaign in **Draft** or **Paused** status. See [Managing Campaigns](/applications/auto-dialer/campaigns).

## Turn detection on

1. Open the campaign's **Edit** form and select the **Answering Machine Detection** tab.
2. Switch on **Enable Detection**. The actions are filled with the defaults below.
3. Set each action.
4. Optionally switch on **Retry on Voicemail**.
5. Save.

## Fields

| Field | Choices | Default when you switch detection on | Applied when |
|-------|---------|--------------------------------------|--------------|
| If Voicemail Detected | Hang up, Continue to destination | Hang up | A beep is heard |
| If Human Detected | Hang up, Continue to destination | Continue to destination | Not reported by the current detector (see below) |
| If Detection Unclear | Hang up, Continue to destination | **Hang up** | No beep within the detection window |
| Retry on Voicemail | On or off | Off | A beep is heard and the number has attempts left |

The form also shows a **Remote CXML URL** choice and URL boxes for each action. The server accepts only **Hang up** and **Continue**; a URL is refused when you save.

An action left empty is treated as **Continue**.

## What happens on a call

1. The callee answers. Cloudonix connects the call to the campaign's [routing destination](/applications/auto-dialer/routing-destinations) **and at the same time** starts streaming the callee's audio to the AMD worker. Detection does not delay the conversation.
2. The AMD worker accepts the stream only if it belongs to a known, active auto-dialer call. Any other stream is closed.
3. The worker listens for a beep: a steady tone between about 300 and 1000 Hz. Two detectors run side by side, a trained model (`beep_ml`) and an energy-based tone detector. A tone that starts in the first **2 seconds** of the stream is ignored, because voicemail beeps come after a greeting and a tone at answer time is usually line noise.
4. The first verdict wins, and there is exactly one per call:
   - **Voicemail**: a beep was heard.
   - **Unknown**: no beep within the detection window (**30 seconds** by default).
5. OPBX looks up the action on the campaign (never from the worker's message), records the result on the call, and:
   - **Hang up**: ends the call through Cloudonix.
   - **Continue**: does nothing; the conversation goes on.

Timings are set on the AMD worker: `AMD_DEFAULT_TIMEOUT_SECONDS` (default 30) and `AMD_MIN_BEEP_START_MS` (default 2000). See [AMD Worker](/workers/amd-worker).

:::warning The detector does not recognise a human voice
The current detector only listens for a beep. It never reports **Human**, so **If Human Detected** has no effect. A call answered by a person ends with **Unknown** when the detection window closes. With the default **If Detection Unclear = Hang up**, every call that does not reach a voicemail is **hung up after about 30 seconds**, including live conversations. For most campaigns set **If Detection Unclear** to **Continue to destination**.
:::

## Retry on Voicemail

When a beep is heard, **Retry on Voicemail** is on and the number still has attempts left (see Max Dial Attempts on the Advanced tab), the number goes back to **pending** and is retried after 5 minutes, then 10, 20, 40 and at most 60 minutes. The attempt still counts. When the attempts are used up, the number is closed according to the call's outcome, normally **Completed** because the voicemail box answered.

## Where the result appears

| Place | What you see |
|-------|--------------|
| Campaign detail page | The **Voicemail** card counts calls where a beep was heard |
| Real-Time Monitor | **Voicemail** on each campaign card and **Voicemail Detected** in the drill-down |
| [Call Logs](/modules/call-logs) | The **AMD Status** column on each call |
| List detail page | The number's last result |

## Turning detection off

Switching **Enable Detection** off in the edit form does **not** clear the actions already saved, so detection stays active after you save. To stop it, set all three actions to **Continue to destination** (detection still runs but never acts), or clear the actions through the API (`action_voicemail`, `action_human` and `action_unknown` set to `null`).

## Troubleshooting

| Symptom | Likely cause | What to do |
|---------|--------------|-----------|
| Live calls end after about 30 seconds | **If Detection Unclear** is Hang up | Set it to Continue to destination |
| Voicemail is never detected | The AMD worker is down, or the webhook base URL is not set | Check the worker's health and the Cloudonix settings |
| A real beep is missed | The beep came within the first 2 seconds, or the greeting was longer than the window | Raise `AMD_DEFAULT_TIMEOUT_SECONDS`; lower `AMD_MIN_BEEP_START_MS` with care |
| Calls are hung up on a ringback or tone at answer | A steady tone after the 2-second gate | Raise `AMD_MIN_BEEP_START_MS` |
| Saving fails with "The selected voicemail action is invalid" | A Remote CXML URL was entered | Use Hang up or Continue |
